## 1. 三个密度因素（不得混淆）
| 因素 | 含义 | 取值 |
|---|---|---|
| Training Density | 训练时输入 P1 的 BAND 来源；它同时决定 UNKNOWN 掩码和 b / y 标签 | S10（模拟器存储的 10% 采样点）/ D100（全部有效深度像素，`p1_full.P1FusionFull`） |
| Inference Density | 规划时送入模型的 P1：粗网格、11 个投影通道、解码时的 UNKNOWN 采样 | S10 / D100 |
| Scoring Density | DistP1 判定“新颖”的 band_dil 来自哪张 P1 | S10 / D100 |

- 两种 P1 都只来自同一组真实观测记录（service records）：EMPTY 由整幅深度雕刻，两者相同；只有 BAND 点集不同。
- 不读取任何未观测的 GT 几何。GT 只用于评估：t\*、真实新像素、oracle 覆盖增益。

## 3. 固定状态（Task 1 + Task 2）：3 × 2 × 2 = 12 组
**状态集**：与历史 E2 G1 / G2 完全相同。
- **MP3D VALSEL**：9 条轨迹、90 个状态、6 个房屋；oracle 见 `e2/valsel`。
- **Macarons++ Dev-3**：barts、pantheon、colosseum 三个场景，共 275 个状态，分为 B0 层 150 个（Task 2 V2M 轨迹）和 B2 层 125 个（Task 3 B2 闭环轨迹）。

**回放**：`scripts/da_fixed.py`，直接导入 `e2_fixed.py` 的 Rep、states、pred_groups，不做任何修改。
- **规划区域**：室内在 r = t − t % 10 处以 n_win = 5 重建区域，回放第 0..r 条记录后再逐步增量写入；室外使用整场景网格。
- **两张地图同时维护**：S10 和 D100 由同一组记录各自独立积分，与闭环 P1FusionB2 的双图方式相同。
- **编码**：每个刷新块，每个 (checkpoint, 推理密度) 用对应地图的粗网格编码一次。
- **Flow 噪声**：每个刷新块只有一个噪声，种子键沿用历史（VALSEL 为 `exp5-T3E2|valsel|…`，Dev-3 为闭环键），12 组配置共用。

**严格配对**：同一状态下，12 组配置的以下各项完全相同：观测历史、候选集合、射线几何（o、d、dz、tcap）、噪声、K = 4、10 步 Euler、64 × 114。两组不同推理密度之间，只有输入 P1 不同。

**评分**：对同一 (checkpoint, 推理密度) 只生成一次未来深度，然后分别用 S10 和 D100 的 band_dil 调用同一个 `scoring.new_set_from_depth` 打分。DistP1 公式、体素去重、距离权重都不变。
- 推理密度与评分密度不同的组（S10 / D100、D100 / S10）是**受控消融**，不是“同一信息使用协议”。

**回归检查**（任一不符即 STOP）：
- 4 组历史配置与 `e2/fixed/<set>_s5000` 的历史行**逐位相等**：
  - B2|S10|S10 = 历史 B0；
  - B2|D100|S10 = 历史 B2；
  - E2S|S10|S10 = 历史 S10；
  - E2D|D100|S10 = 历史 D100。
- B2|D100|D100 与 E1.2 的 own-D100 行逐位相等（仅 Dev-3）。
- 从 D100 地图 input_volume 重算的 band_dil（即闭环“评分图”路径）与 SceneCaster 自带的 band_dil 逐位相等。
- 历史 pred_groups（G1 量）是否一致，同样记录。

### 3.1 G1 预测质量（射线集合与分母必须写明）
| 射线集合 | 定义 |
|---|---|
| `unk_common`（**主比较**） | 在 S10 和 D100 两张图中都是 UNKNOWN 的射线：两种推理密度都由模型预测，可逐射线配对比较 |
| `unk_only10` | S10 下 UNKNOWN、D100 下已知或为空：S10 推理是模型预测，D100 推理直接取地图的 t_known |
| `unk_only100` | D100 下 UNKNOWN、S10 下不是（预期很少） |
| `unk_own` | 当前推理密度自己地图中的 UNKNOWN（历史 G1 的口径；两种密度的分母不同，不能直接比较） |
| `unk_union`、`all` | 并集、全部射线 |
| `new_common` | `unk_common` 中 GT 为真实新表面的射线（GT 点到所有过去 10% 采样点的距离大于覆盖 eps） |

每个集合都按 K × 射线累计，统计量如下：

| 统计量 | 定义 |
|---|---|
| n | 射线数 × K |
| gt | GT 有命中 |
| ph | 预测有命中 |
| tp | 预测与 GT 都命中 |
| fp | 误报命中（预测命中、GT 无命中） |
| fn | 漏报（GT 命中、预测无命中） |
| tn | 都无命中 |
| sae | tp 上的深度绝对误差之和。单位 u：室内 1 m，室外 1 个运行时单位 |
| acc | 准确首中：tp 且 \|err\| ≤ trunc + 1%·z |

由此导出的指标：
- MAE = sae / tp；
- 首中 / 无中准确率 = (tp + tn) / n；
- 误报率 = fp / (fp + tn)；
- 漏报率 = fn / gt；
- 命中率 = ph / n；
- 准确首中率 = acc / gt。

另外记录 K = 4 的 spread（历史 pred_groups 口径）。

### 3.2 G2 相机选择
- **选择规则**：12 组配置都用历史的 Task 2 选择规则（`ab_load.pick_of`；室内为 nv_choice，室外为 choose），分数为 K = 4 的 DistP1 均值。
- **Oracle 增益**：来自 oracle.npz 的 gain（GT 覆盖增益，单位 pp），与评分密度无关，12 组完全相同。
- **指标**（候选集合 C 与历史 G2 相同）：
  - Top-1（选中候选的增益 ≥ 最大增益 − 0.01 pp）；
  - 选中候选的真实增益（pp）；
  - oracle 最大增益；
  - regret（只放附录）；
  - Spearman 和 Kendall（分数 vs 增益）；
  - 不同配置之间选择改变的比例；
  - 分数尺度（候选分数的均值、分数为 0 的候选比例）。

### 3.3 评分掩码诊断（SCORING_ABLATION）
- 对每个 (checkpoint, 推理密度, 评分密度)，统计解码命中点中：
  - 被 band_dil 排除的（不算新颖）；
  - 被奖励的（算新颖）；
  - 按像素真值拆分：被排除但其实是真实新表面、被奖励但其实是旧表面、被奖励但 GT 无命中。
- GT 深度本身在 S10 和 D100 两种 band_dil 下也做同样统计。

### 3.4 统计
- **层级均值**：状态 → episode → 场景。
- **主统计**：场景级配对 bootstrap（10,000 次，seed 0），与历史 G1 / G2 相同。VALSEL 有 6 个房屋，Dev-3 只有 3 个场景，所以 CI 很宽。
- **辅统计**：episode 级配对 bootstrap（VALSEL 9 个 episode，Dev-3 30 个 episode）。
- 室内、室外分开报告，不合并。
- **只有 95% CI 不含 0 才称为“确定”**。CI 含 0、但方向一致（胜负比或 episode 级 CI）的，称为“趋势”。

## 4. 闭环 G3（Task 3）
**协议**：与历史完全相同。
- MP3D：5 个 val 楼层 × 2 个起点 = 10 个 episode，每个 150 步。
- Macarons++：Dev-3 + Test-3，6 个场景 × 5 个起点 = 30 个 episode，每个 100 步。
- R10、K = 4、Greedy-NV、室内 n_win = 5。
- 真实覆盖口径：室内为 C_obs，室外为单调覆盖（monotone coverage），与评分密度无关。

**P1 模式**：`scripts/da_p1.py`。
- s10s10 = `p1_full.patch("sparse")`
- d100s10 = `patch("b2")`
- d100d100 = `patch("full")`
- **s10d100（新增）**：输入为 S10 的冻结类，另外维护一张 D100 评分图；Geometry 只把 caster.band_dil 换成评分图的版本，计算方式与 `p1_full._patch_geometry_b2` 相同（b2 的镜像）。
- Checkpoint 由 `T3_CKPT` 环境变量传入，与历史 E2 相同。

**可复用的历史 G3（5 组）**：

| B2\|D100\|S10 | B2 | 0.334 / 0.530 | 0.730 / 0.906 |
| B2\|D100\|D100 | B1 | 0.330 / 0.472 | 0.691 / 0.869 |

**G0 闭环复现**（复用历史结果的前提）：

- 要求执行的动作序列和覆盖曲线与历史**逐位相同**；不相同就 STOP，并排查后报告，**不复用历史结果**。
- 同时用历史 episode 文件重新计算这 5 组的 AUC / Final，必须等于报告值。

**新跑的 7 组**：
- **第一批（优先，组成 8 组关键配置）**：B2\|S10\|D100、E2S\|D100\|S10、E2S\|D100\|D100、E2D\|D100\|D100。
- **第二批**（补齐 12 组）：E2S\|S10\|D100、E2D\|S10\|S10、E2D\|S10\|D100。
- 第二批在第一批完成后运行。若只完成部分，矩阵不得标为“完整”。

**指标**：
- AUC（室内 @150，室外 @100）、Cov@20、Cov@50、Final；
- 每步真实覆盖增益；
- MP3D 停滞：t ∈ [30, 120] 内 ≥ 30 步覆盖增长 < 0.01，与历史定义相同；
- 重访率；
- 每步决策时间、峰值显存。

**统计**：
- 场景级配对 bootstrap 95% CI（MP3D 5 个场景，Macarons++ 6 个场景），附胜 / 负数。
- 逐场景覆盖曲线。
- 闭环轨迹因策略不同而不同，**只用于评价系统收益，不用于单步预测归因**。
