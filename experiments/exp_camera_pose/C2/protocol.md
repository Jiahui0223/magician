# C2 —— Smooth & Continuous Camera Pose：预注册协议 v1.0（2026-11-02，在任何 C2 结果之前冻结）

范围：只做 MP3D 室内。Macarons++ 官方环境只执行 `pose_space` 网格索引，C2 不修改它（见 `../reports/AUDIT.md`）。
- 不训练，不改模型、Ray Encoder、Flow、K = 4 和 DistP1。
- B2 / E2-D100 必跑（D100 输入 / S10 评分）；V4 / V5 视资源决定。
- 评估场景非盲。

## 1. 位姿格与候选族（实现：`scripts/c2_poses.py`）
**细格**：位置为 1/4 原格（约 0.25 m），俯仰 5°（范围 −60…+60，与原范围相同），偏航 5°。原网格位姿精确落在细格上，即 `(4l, 4w, 4h, 6e, 9a)`。

| 族 | 偏移（相对当前位姿） | 新增数 |
|---|---|---|
| C0 | 原邻居：单轴 ±1 格、俯仰 ±30°、偏航 ±45° | ≤ 10 |
| C2a 方向 | 位置不变；偏航 ±10°、±20°；俯仰 ±5°、±10° | 8 |
| C2b 位置 | 朝向不变；x / 高度 / y 三轴各 ±0.25、±0.5 格；水平对角 (±0.5, ±0.5) 格 | 16 |
| C2c 联合 | 水平 8 个方向 × 0.5 格（轴向 0.5、对角 0.5/0.5）× 偏航 ±20°；高度 ±0.5 格 × 俯仰 ±10° | 20 |

- 变体 Cx = C0 ∪ Cx 新增（保留全部 C0 合法候选）。ALL = C0 ∪ C2a ∪ C2b ∪ C2c，只用于诊断。
- 所有新增平移都 ≤ 1 原格（C0 的步长）：对角 0.71 格，轴向 ≤ 0.5 格。所以 C2 不会靠更大的单步移动获益。

**合法性**（模拟器侧，GT 只用于运动约束）：
- 终点在原网格中心的包络内；俯仰在 [−60°, 60°]；
- 当前位置到目标位置的直线段不与 GT 网格相交（与原 `legal_actions` 同一个 Blocker）。路径是直线，所以这就是整条路径的检查；
- 纯旋转总是合法；去掉当前位姿和重复项。
- 规划器的“优先未访问”按细格索引判断。

**执行路径**：Kinematic Smooth Path——位置线性插值，偏航走最短弧，俯仰线性插值。只在终点获取一次观测，插值点不观测。记录平移距离（m）、|Δyaw|、|Δpitch|。

**候选生成不使用任何 GT 收益**：偏移表是固定的，只按几何合法性过滤。

## 2. Stage A：固定状态 Oracle（不跑 Flow）
- **状态**：MP3D VALSEL 开发固定状态，9 条轨迹 × 10 个时刻 = 90 态。房屋与 G3 的 MP3D 房屋不重叠。
- **Oracle 计算**：与 `e2_valsel_oracle.py` 完全相同——覆盖由 0..t 的记录重放，下一帧采样使用轨迹自己的种子，ε 相同。
- **回归检查**：C0 候选的增益必须与已存的 `oracle.npz` 逐值相等。
- **可选集合**：按规划器规则取“优先未访问”的子集。
- **主指标**：每态 Δ = OracleBest(Cx) − OracleBest(C0)，单位 pp。

**Stage A 放行**（每个变体分别判定）：
1. mean Δ ≥ max(0.10 pp, 10% × mean OracleBest(C0))；
2. 至少 25% 的状态 Δ > 0，且 Δ 最大的 10% 状态贡献不超过 ΣΔ 的 60%；
3. 变体 oracle 最优动作的平均平移 ≤ C0 oracle 最优动作的平均平移 + 0.25 m。

三个变体都不通过时，**C2 结论为 NO-GO，停止**，不跑模型，也不跑闭环。

另外报告：
- 候选数、越界 / 碰撞剔除率；
- 最优候选所属的族；
- 最优位姿相对原格点的偏移（位置 / 偏航 / 俯仰）；
- 每米增益；
- 联合动作与单独改动作的比较。

## 3. Stage B：冻结模型的固定状态选择（只对通过 A 的变体）
- **模型**：B2、E2-D100（必跑）；V4、V5（探索）。
- **评分**：在同一状态、同一地图、同一 R10 编码、同一 Flow 噪声下，对扩展候选打 DistP1，按原规划器规则（`nv_choice`）选择。
- **回归检查**：C0 子集的 DistP1 必须与历史 B2 / E2 行一致。若批组成不同导致数值差异，报告最大偏差。
- **指标**：Oracle Best、Selected Real Gain、Top-1、选中新候选的比例、Winner's Curse 诊断（选中新候选时预测分数与真实增益的对照）、单步耗时。

**数量匹配对照**：从 ALL 池中按固定种子 `sha256("C2|ctrl|<sid>")` 随机抽取与该变体相同数量的候选，不使用 GT，用同一模型同一规则选择。

**放行**（每个模型）：mean Δselected（Cx − C0）≥ +0.05 pp，且房屋级 bootstrap 95% CI 下界 ≥ 0。B2 与 E2 至少一个通过，才进入 Stage C。

## 4. Stage C：短闭环 Pilot（新动作协议，室内）
- **模拟器**：`scripts/c2_in_sim.py`。它是 Task 2 的 `t23_in_sim` 原样运行，只替换 `grid_env` 的位置 / 角度函数和 `legal_actions`。
- **回归检查**：C0 族在新模拟器中必须与原 C0 逐步一致。
- **episode**：VALSEL 的 4 个（与 C1 pilot 相同），起点和种子相同。
- **条件**：C0（新模拟器）、Cx（通过 A / B 的变体）、数量匹配随机对照（每步从 ALL 的合法池中按种子抽取）。

**指标**：
- AUC、Final、Cov@20、Cov@50；
- 累计路径长度（m）、总旋转量（°）、单位路径长度的覆盖率、不同位置数、碰撞剔除数；
- 插值点不计观测。不编造飞行时间或能耗。

**放行完整 G3**（每个模型）：
- mean ΔAUC（Cx − C0）≥ +0.01；
- 没有 episode 的 ΔAUC < −0.03；
- mean ΔFinal ≥ −0.01；
- Cx 的 mean AUC ≥ 随机对照。

## 5. Stage D：完整 MP3D G3（条件执行）
- **范围**：10 episode × 150 步，起点与覆盖定义沿用历史。B2 / E2 必跑，V4 / V5 视资源。
- **报告**：AUC、Final、Cov@20、Cov@50、路径长度 / 旋转；配对 ΔAUC 与楼层 bootstrap CI。
- **比较方式**：
  - (A) 旧协议 C0 vs 新协议 C2：系统级比较；
  - (B) 同一新协议下 C0 vs C2：公平比较。

MAGICIAN beam search（MAG-B）只作为系统级参照：它使用原网格，历史 G3 为 MP3D 0.292 / 0.377。

## 6. 结论规则
- **GO**：完整 G3 上 B2 或 E2 的 ΔAUC（同一新协议）> 0，且 CI 不含 0，路径成本没有异常。
- **NO-GO**：A、B、C 任一门槛不通过，或完整 G3 无改善。
- **INCOMPLETE**：必跑部分没有完成。
