# C2 —— Smooth & Continuous Camera Pose：最终报告（2026-11-02）

## 结论：**NO-GO**
在 MP3D VALSEL 的 90 个开发固定状态上，更细的候选只带来很小的一步 oracle 收益，**三个变体都没有通过预注册的 Stage A 门槛**：

| 变体 | 内容 | oracle 收益（相对 C0） |
|---|---|---|
| C2a | 更细朝向 | +0.013 pp（+1.2%） |
| C2b | 更细位置 | +0.031 pp（+2.8%） |
| C2c | 位置 + 朝向联合 | +0.084 pp（+7.7%） |

门槛要求 mean Δ ≥ 0.11 pp，且收益不能集中在少数状态。按协议，**没有运行模型选择（Stage B）、闭环 pilot（Stage C）和完整 G3（Stage D）**。

因此不存在 C2 的覆盖率曲线或 AUC，也不能声称 C2 改善了探索。

本报告还附带了用户要求的附加比较：B2 / E2-D100 / V4 / V5 的 C0 与 C1，以及 MAGICIAN beam search，都在同一组 pilot episode 上（§10）。所有评估场景都是此前用过的非盲场景。

## 1. C2a / C2b / C2c 的实现（`scripts/c2_poses.py`，冻结于 `protocol.md`）
**细格**：在原 MP3D 网格（约 1 m、俯仰 30°、偏航 45°）之上，位置取 1/4 格，俯仰 / 偏航取 5°。
- 原网格位姿精确落在细格上：`(4l, 4w, 4h, 6e, 9a)`。
- 俯仰范围保持原来的 −60°…+60°。

| 族 | 偏移 | 新增 |
|---|---|---|
| C0 | 原邻居：单轴 ±1 格 / ±30° 俯仰 / ±45° 偏航 | ≤ 10 |
| C2a | 位置不变；偏航 ±10°、±20°；俯仰 ±5°、±10° | 8 |
| C2b | 朝向不变；三轴各 ±0.25 / ±0.5 格；水平对角 (±0.5, ±0.5) 格 | 16 |
| C2c | 水平 8 方向 × 0.5 格（对角 0.71 格）× 偏航 ±20°；高度 ±0.5 格 × 俯仰 ±10° | 20 |

- 各变体都保留全部 C0 合法候选。
- 所有新增平移 ≤ 1 原格，所以 C2 不会靠“一步走得更远”获益。
- **候选生成只用固定偏移表和几何合法性，不用任何 GT 收益**。

**实际修改**：只新增了 C2 的脚本（位姿生成、oracle、分析、可视化、smoke）。没有改模拟器、渲染器、覆盖率、规划器或模型。原模拟器的位姿函数在 C2 进程中被替换为细格版本：渲染接口 `Sensor.RT` 本来就接受浮点位置和角度。

## 2. 连续位姿与平滑轨迹的合法性检查
**Task 0 审计**（室内模拟器 `t12_sim` / `t23_in_sim` / `mp3d_sim`）：
- **渲染**：`Sensor.RT(X_rt, elev, azim)` 通过 MAGICIAN 的 `get_camera_RT` 接受任意浮点位姿。分辨率 456×256，垂直 FOV 60°（水平约 92°），量程 70 运行时单位（10 m），单位为运行时（7 × 米）。
- **碰撞**：GT 网格线段求交（Blocker）对任意两点有效。
- **覆盖率（C_obs）**：只依赖观测采样点，与网格无关。

**网格外 smoke**（`scripts/c2_offgrid_smoke.py`，结果在 `work_dirs/exp_camera_pose/C2/smoke/`）：
- 执行 VALSEL 8194nk5LbLH t=5 的 C2c oracle 最优位姿：对角 0.70 m + 偏航 20°，不在原格上，真实一步收益 4.06 pp。
- 渲染 → 10% 采样（11,242 点）→ 规划器格式的服务记录，通过 `validate_service_record`。
- 写入 D100 P1：EMPTY +2.29 M 体素，UNKNOWN −2.44 M，BAND +0.15 M。
- B2（registry checkpoint）对新位姿的 23 个 C2c 候选打 DistP1：全部有限且非零，打分约 2.4 s。

**Stage A 中的合法性**：共生成 4,860 个 ALL 候选，其中越界剔除 15.5%，GT 线段碰撞剔除 6.7%。
- C0 子集与历史合法列表逐个比对：R、T 和真实增益**逐值相等**；C0 oracle 均值 1.099 pp，与历史完全一致。
- 不合法候选不进入集合，因此进入 oracle 的候选中不合法动作率为 0。

**轨迹定义（未执行）**：只定义了 Kinematic Smooth Path——位置直线插值（线段检查即覆盖整条路径）、偏航取最短弧、俯仰线性插值，只在终点观测。由于 Stage A 未通过，没有实现 C2 闭环模拟器，也没有执行任何 C2 轨迹，所以没有路径长度 / 运动成本的闭环数据。

## 3. 原网格 vs 连续位姿的 Oracle Gain（Stage A，`reports/stage_a.md`）
| 变体 | 合法 / 可选候选 | Oracle best（pp） | Δ vs C0 | 改善的状态 | top-10% 状态贡献 | 最优来自新候选 | 门槛 |
|---|---|---|---|---|---|---|---|
| C0 | 7.8 / 6.7 | 1.099 | — | — | — | — | — |
| C2a | 15.4 / 14.4 | 1.112 | +0.013（+1.2%） | 16% | 99% | 17% | ❌ |
| C2b | 19.8 / 18.7 | 1.130 | +0.031（+2.8%） | 24% | 96% | 24% | ❌ |
| C2c | 22.4 / 21.3 | 1.183 | +0.084（+7.7%） | 47% | 76% | 48% | ❌ |
| ALL（诊断） | 42.0 / 40.9 | 1.195 | +0.096（+8.7%） | 52% | 71% | 52% | — |

- 门槛：mean Δ ≥ 0.110 pp（= max(0.10, 10% × 1.099)）；至少 25% 的状态改善，且 Δ 最大的 10% 状态贡献 ≤ 60%；平移成本合理。
- C2c 最接近通过，但均值和集中度两条都没达到。

**分阶段**（mean Δ，pp）：C2c 在早期（t ≤ 25）+0.145，中期 +0.104，后期 +0.013。收益主要在探索初期，那时一步的选择空间本来就大。

**分房屋**：C2c 在 8194nk5LbLH +0.223、EU6Fwq7SyZv +0.118，在 pLe4wQe7qrG 和 zsNo4HB9uLZ 只有 +0.01 / +0.02。

**最优位姿离原网格多远**：
- C2c 最优为新候选时，几乎全是“0.5 格水平 / 对角平移 + 偏航 20°”：39 / 43 次 |Δyaw| = 20°，平均平移 0.61 m，全部不在原格点上。
- C2a 胜出时，多为偏航 ±10° / ±20°，俯仰很少起作用（13 / 15 次 Δpitch = 0）。

**联合 vs 单独**：C2c 最优严格优于 max(C2a, C2b) 的状态占 40%，平均多 +0.041 pp。**位置 + 朝向联合调整确实比只改一项更好**，但绝对量仍然很小。

**是否只是动作更大**：不是。
- 各变体 oracle 最优动作的平均平移：C0 0.45 m、C2c 0.48 m、ALL 0.46 m。
- 按“增益 / (平移 + 0.25 m)”计：C0 4.02、C2c 3.78、ALL 3.79。新候选的单位移动收益没有更高。

**可视化**：
- `reports/figures/stage_a_oracle.png`：逐状态 Δ 的排序、集中度、分阶段。
- `reports/figures/pose_distribution.png`：两个成功状态和两个无收益状态的俯视位姿分布，含原网格候选、新候选、偏航箭头、GT 网格（仅可视化）、oracle 最优。

## 6. 动作距离与旋转成本的公平性
- **一步内的公平性**：所有新增平移 ≤ 1 原格，旋转 ≤ 20°（< C0 的 30° / 45°）。所以 C2 新候选的单步移动量不大于 C0，oracle 的比较不会偏向“动作更大”的一方（见 §3 的每米增益）。
- **一步之外**：没有执行多步，也就没有累计路径或旋转数据。观测预算按“每个动作一次观测”定义，插值点不观测；由于没有闭环运行，这一规定没有被实际使用。

## 7. 典型成功与失败场景（`reports/figures/pose_distribution.png`）
**成功**：8194nk5LbLH t=5（+1.37 pp）、EU6Fwq7SyZv L2 t=5（+1.06 pp）。
- 都是探索早期、视野开阔的房间。
- 最优是对角 0.5 格平移 + 偏航 20°：同时改变观察位置和方向，看到原网格动作看不到的墙面。

**无收益**：X7HyMhZNoso L1 t=0、pLe4wQe7qrG t=0。
- 起始状态下，C0 的原地 45° 旋转已经能看到新的大片区域（最高 16.6 pp），更细的偏移不会更好。
- 在走廊、遮挡较多的位置，GT 碰撞剔除了一部分对角候选。

## 8. 与原始 C0 的差异
- C0 已经包含原地旋转和单轴平移。细化角度（C2a）几乎没有用：原 45° 偏航步长约为水平 FOV 的一半，相邻朝向的视野高度重叠。
- 细化位置（C2b）在近 1/4 的状态有用，但量很小。
- 联合调整（C2c）最有用，但 0.084 pp 只占 C0 oracle 的 7.7%，而且集中在早期和少数房屋。
- 模型本身离 C0 的 oracle 还差约 0.2 pp（§4）。这说明瓶颈仍在排序质量（未来深度 / DistP1），不在候选分辨率。

## 11. 结论与建议
- **C2：NO-GO**。在当前室内协议下，把位置 / 角度分辨率加细、或者允许平移 + 旋转联合，一步 oracle 上限只提高 1–8%，并且集中在探索早期和少数房屋。原 5D 网格**不是**限制最佳观察视角的主要因素。
- **C1：仍为 NO-GO**。附加的 V4 / V5 探索性 C1 结果正负混杂，没有改变结论。
- **结论**：两个方向都表明，Camera Pose 一侧（候选选择或候选分辨率）的空间很小；真正的差距在于模型对现有候选的排序（selected 约为 oracle 的 80%）。**Camera Pose 阶段到此结束**，下一步方向由你决定，我不会自动开始 DAPS、Planner 或新模型。
