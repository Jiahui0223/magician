# FINAL_AUDIT_REPORT — MAGICIAN 评估与训练协议审计结论

**日期**：2026-11-04。逐项证据见 `AUDIT_CHECKLIST.md`（41 项）及各子文件。

## 1. 总体结论
**我们的 CVPR Table 1 与 MAGICIAN 官方发布的代码、数据和起点完全一致，内部可比性很强**：
- 所有方法在同一个评估器下运行；
- 使用同样的 5 个起点和 100 步预算；
- 采用同一套覆盖率与 AUC 定义；
- 最大的协议差异只是无合法动作时的处理，而主表模型从未触发。

**与 MAGICIAN 论文公布值之间的差距，不能完全解释**：
- 复现 MAGICIAN 的 All-14 比论文低：AUC 0.010（CI 含 0），Final 0.015（显著）；
- 差距集中在 4 个场景；
- 论文的 GT 点云定义与发布的代码不同，论文也没有公布起点，无法离线消除。

## 2. 关键事实
- **起点**（PASS）：
  - 我们 26 个模型的 1655 条 episode 都从 `settings.json start_positions[k]` 出发；
  - 与 MAGICIAN 上游循环的复现运行 70 / 70 完全一致；
  - 没有重复、缺失、错位或挑选。
  - “论文实际用的就是这 5 个位姿”无法验证（UNKNOWN）：官方 README 称它们是“随机采样的 5 个起点”，但论文没有发布轨迹。
- **评估器**（PASS，针对发布代码）：
  - GT 采样、覆盖计算、10% 点采样、邻居与合法规则等关键函数在官方代码与我们的 fork 中逐字相同；
  - 唯一的差异是 fork 多出一行导致 sofia_church 无法加载的 `torch.tensor()`（官方 2026-08-29 才修复），以及一段只用于随机位姿采样的 occupied-pose 代码。
- **公式**（PASS）：
  - AUC@k = trapz(C[0..k]) / k，含两端点，已用单元测试验证；Final = C[100]；
  - 先场景内平均，再场景等权平均；
  - 官方的 `evaluation_lmdb.py` 写法不同，但在同一数据上相差 ≤ 0.009，且都低于论文值。
- **论文 vs 复现**（UNRESOLVED）：
  - 两份独立复现（设种子的冻结模拟器 vs 上游循环原样运行、不设种子）彼此一致：AUC 0.7108 vs 0.7111；
  - 与论文的 All-14 差距主要来自 pantheon（−0.083 / −0.102）、neuschwanstein、sestino_museum、bannerman 中几个对所有方法都难的起点；
  - 可能的原因有三：论文用渲染的可见点作 GT（附录 B.1）、论文的起点不同、论文时期的代码版本不同。**都无法确认。**
- **论文内部不一致**（FAIL，论文侧）：表 7 中 FisherRF 的平均 Final 写作 0.786，而它 15 行的均值是 0.772。
- **训练**：
  - **MAGICIAN**：没有自己的权重，用的是 MACARONS 的 `trained_macarons.pth`。这份权重先在 ShapeNet 预训练（推断），再在 8 个场景上自监督训练，**这 8 个场景都在我们 14 个评估场景中**。训练起点在全网格随机抽取，与评估起点恰好重合的期望很低，但无法核实。
  - **我们的模型**：
    - 室外数据只来自 Train-6 去掉 S-c；Dev-5、Test-3 没有任何训练数据；
    - 每个 Train-6 场景有 3 个官方起点是训练轨迹的起点；
    - Y50K、D1 按 Dev-5 选出；Test-3 不是盲测；
    - 混合模型（B0 / B2、E2、V3、Y）另用了 MP3D。
- **对已有审计的 4 处更正**（以本次为准，原文件未改）：
  - S-c 是 42 条，不是 44 条；
  - “官方 MACARONS 用完美深度训练”没有依据，证据指向 RGB 自监督；
  - “alhambra / neuschwanstein 被用来选 checkpoint”没有依据；
  - MP3D 实际用于训练的是 59 个房屋，不是 61 个。

## 4. 尚未解决的协议差异
1. **GT 点云**：论文附录 B.1 写的是渲染的可见点，发布的代码是 mesh 采样再除以 visibility_ratio。论文的 GT 没有公开，无法重算。
2. **起点**：论文没有发布它实际用的 5 个位姿，与官方 settings 的一致性无法证实。
3. **论文时期的代码版本**：当时的官方代码无法加载 sofia_church，说明论文结果不是用发布的代码版本产生的。
4. **种子**：官方不设种子，我们设种子。只影响评估噪声，且两份复现一致。
5. **无合法动作时的处理**：官方结束轨迹，我们原地停留一步。主表模型从未触发，没有数值影响。
6. **训练侧未知项**：U1–U9，例如论文中 SCONE / FisherRF 列实际用的权重、MACARONS 的 val 用途，见 `MAGICIAN_TRAINING_AUDIT.md` §E。

## 5. 建议的补充验证（都不需要训练）
1. **在冻结评估器之外，用官方修复后的加载函数跑 sofia_church**：作为 protocol v1.1，单独标注；需要为我们的规划器补 `em2_windows` 条目。完成后才能给出 All-15。
2. **用发布的代码跑一遍 SCONE / MACARONS 的测试器**：需要先修复上游已知的问题。这样它们才能进入复现组，与我们公平比较；在此之前只能引用论文值。
3. **向 MAGICIAN 作者索取论文的起点与 GT 点云**：这是解决 Paper vs Reproduced 差距的唯一直接途径。
