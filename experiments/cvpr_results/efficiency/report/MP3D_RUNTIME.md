# EXP8-MP3D：室内计算效率（2026-11-11 06:15，全部为真实测量）

**测法：** 与 EXP8 室外相同，见 `BENCHMARK_PROTOCOL.md`。逐步重放 EXP7 MP3D-150 的真实轨迹，用的是 RAYSCOUT 自己的轨迹，读取它的服务记录（`work_dirs/cvpr_results/exp7/episodes/mp3d150/raw/OURS/V2M/<tag>/svc`），喂给冻结的室内规划器子进程：
- RAYSCOUT：EXP7 `d_in_planner.py`，外加同步计时器 `scripts/eff_in_prof_planner.py`。
- MAGICIAN：`magician_planner_grid.py --method MAG-B`。

两种方法每一步看到的观测完全相同。

**选择与资源：**
- 轨迹：22 个楼层按网格大小排序后每 3 个取 1 个，共 8 条，各用第一个起点；每条 150 步。规则在运行前确定。
- 主窗口：t = 10..149，每条 140 个决策，包含 14 次区域刷新。
- 资源：sbatch 3494639（RAYSCOUT，gpu112 GPU 3）、3494640 / 3494642（MAGICIAN，gpu113 GPU 0 / 1），各独占一张 NVIDIA L40S。

**有效性：**
- RAYSCOUT 在 8 条轨迹上逐步重放，每条 150 / 150 步的选择与 EXP7 的记录相同。
- 计时器开销：同轨迹上不带计时器 / 带计时器的计算周期中位数分别为 2.916 / 2.927 s（EU6Fwq7SyZv）、4.287 / 4.320 s（TbHJrupSAjP），选择 150 / 150 相同。

**配对（同一轨迹、同一步，n = 1120）：**
- 决策延迟：MAGICIAN / RAYSCOUT 中位数之比 1.28，RAYSCOUT 在 921 / 1120 个状态上更快。
- 每条轨迹的比值在 0.94 到 1.85 之间。其中 Z6MFQCViBuw_L0，即网格最大的楼层，MAGICIAN 更快。
- 计算周期：中位数之比 1.23（806 / 1120 个状态 RAYSCOUT 更快），但均值是 RAYSCOUT 更慢：5.12 s 对 4.74 s。原因是室内 RAYSCOUT 规划器每 10 步刷新区域时，会把记录 0..t 全部重新融合进新的区域地图，这一步随 t 线性变长，后期 P95 达 17 s。这是冻结的室内规划器（T0.6 / EXP5 Task 2 设计）本身的实现方式，不是生成模型的开销。

## 2. 结论
- 只看决策延迟，室内 RAYSCOUT 也比 MAGICIAN 快，但优势小于室外：中位数 1.28 倍，室外为 1.81 倍；而且网格最大的楼层上没有优势。
- 把在线地图更新算进去，室内 RAYSCOUT 的平均计算周期反而比 MAGICIAN 慢约 8%，原因是区域刷新时重建地图。
- 室内峰值显存明显更高：17.2 GB 对 1.2 GB。
- 因此"更快"的表述只能限定为决策延迟或室外；室内不能宣称整体计算更省。
- 如果改成增量式区域地图，可以去掉重建开销，但那会改动冻结的规划器，本次没有做。
