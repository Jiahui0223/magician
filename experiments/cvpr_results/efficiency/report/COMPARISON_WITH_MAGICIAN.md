# EXP8 与 MAGICIAN beam 的对比（同一 GPU 型号、同一协议、严格配对的输入状态）

**MAGICIAN 的设置：**
- 冻结的官方核心（e697009），beam 宽 10、深 10，官方 settings，默认 fp32。
- 输入是与 RAYSCOUT 完全相同的 7 条真实轨迹的观测序列。MAGICIAN 用这些观测更新自己的内部地图，然后做出决策。
- 另外在 MAGICIAN 自己的 2 条轨迹（eiffel、pisa）上重放：100 / 100 步与 Table 1 的记录相同，决策延迟中位数 6.14 s，与在 RAYSCOUT 状态上测得的值一致。

**配对（同一轨迹、同一步，n = 630）：**
- MAGICIAN / RAYSCOUT 的决策延迟：中位数之比 1.81，均值之比 1.73。
- 630 个状态中 RAYSCOUT 在 619 个上更快。
- 每条轨迹的比值在 1.42（barts）到 1.87（pisa）之间。
- 含地图更新的计算周期：比值 1.68（中位数），RAYSCOUT 在 621 / 630 个状态上更快。

**"预测 / 规划"拆分（只在两条带计时器的轨迹上，见 † 注）：**
- MAGICIAN：占用场 0.77 s / novelty + beam 4.22 s。
- RAYSCOUT：两层生成 2.32 s / 评分与搜索 0.51 s。
- 两种方法的"预测"含义不同：MAGICIAN 是对体积点的占用预测，RAYSCOUT 是逐射线的未来深度。所以不把这两列当作对齐的模块比较，只比较总的决策延迟。

## 不利于 RAYSCOUT 的事实
- **峰值显存更高：** 中位数 3.8 GB，对 MAGICIAN 的 1.4 GB；大场景 dunnottar 达到 30.5 GB。
- **推理用参数更多：** 22.95 M，对 3.65 M。
- **只在 Macarons++ 室外状态上测量：** MP3D 和 UAVScenes 上没有做独立的计时。
- **只比较了 MAGICIAN 一个方法：** MACARONS / SCONE / FisherRF 没有测量。
