## A. 刷新周期 A/B：R10 / R5 / R2 / R1（推理时改动，不训练）
### A.0 为什么需要解耦
当前一次“刷新”同时触发三件事【代码】：
1. 重算 3D 编码 h；
2. 重新生成 Flow 噪声 eps（种子键含 t_r）；
3. 室内重建规划区域，并在新区域里重建 P1 融合。

只改周期，就分不清是哪一个在起作用。因此建议把三个因子拆开：

| 因子 | 取值 | 实现（不改原文件，在新入口里替换） |
|---|---|---|
| **R：编码刷新周期** | 10（基线）/ 5 / 2 / 1 | 室内：新的 Planner.step，把 t06:112 的 `t % 10` 换成 `t % R`；室外：替换 `v2_common.refresh_time` 为 `R * (t // R)` |
| **N：噪声** | `per-refresh`（现状，每次刷新换噪声）/ `anchored`（噪声始终按 R10 的 t_r = 10⌊t/10⌋ 生成） | 在 refresh 中计算种子键时用 t_anchor |
| **G：室内区域** | `coupled`（现状，每次编码刷新都重新居中）/ `anchored`（区域和融合只在 t % 10 == 0 时重建；中间的编码刷新只在当前区域上重算 h） | 拆开 `refresh()` 中区域重建与编码这两步 |

要求：R10 + N-per-refresh + G-coupled 必须与历史逐位一致（回归检查）。

### A.1 建议矩阵
| 编号 | R | N | G（室内） | 回答的问题 |
|---|---|---|---|---|
| A0 | 10 | per-refresh | coupled | 基线（与历史逐位一致） |
| A1 | 5 | anchored | anchored | 纯编码陈旧度的影响（5 步） |
| A2 | 2 | anchored | anchored | 同上（2 步） |
| A3 | 1 | anchored | anchored | 同上（每步都是新编码），**主要对照** |
| A4 | 1 | per-refresh（即每步换噪声） | anchored | 每步换噪声的影响，与 A3 比较 |
| A5（只做室内） | 1 | anchored | coupled（每步重新居中） | 每步重建区域的影响，与 A3 比较 |

- **模型**：B2、E2-D100 必跑；V4、V5 可选，它们走同一规划器，只需换 checkpoint。
- **训练分布**：陈旧增强覆盖 Δ ≤ 9，所以 A1–A5 的陈旧程度都在训练分布之内【代码】。

### A.2 分阶段执行
1. **A-Stage 1：固定状态陈旧度曲线**（不跑闭环，最便宜）
   - 状态：VALSEL 90 + Dev-3 275。
   - 对每个状态，比较两种编码：刷新时的旧编码（陈旧 s = t − t_r ∈ {0..9}，即现状），以及在 t 时刻重新编码。
   - 对比 DistP1 排序：Top-1、selected gain（pp）、选择改变的比例，按 s 分组画曲线。
   - 只改编码时机，噪声和区域固定，相当于 A3 vs A0 的单步版本。
   - 成本：B2 和 E2 各一次固定状态回放，每状态多一次编码；估计 4 卡约 1 小时。
2. **A-Stage 2：短闭环 pilot**
   - episode：开发场景（VALSEL 4 + Dev-3 6），A0–A5 × B2 / E2，同一起点和种子，配对比较。
   - 估计：室内单 episode 约 5–8 分钟，室外约 3–5 分钟；4 卡 8 个 worker 约 2–3 小时。
   - 指标：AUC、Final、Cov@20、Cov@50，以及每步决策时间（R1 每步多一次编码：室外约 0.18 s，室内约 0.5 s；刷新步还要多建一次几何）。
3. **A-Stage 3：完整 G3**（条件执行）
   - 范围：MP3D 10 × 150、Macarons++ 30 × 100。只跑在 pilot 上通过门槛的 (R, 模型, 域)。
   - 每个组合约 1–1.5 小时（4 卡）。

**建议门槛**（确认时冻结）：
- Stage 1 → 2：在至少一个域上，s ≥ 5 的状态中，新编码的 Top-1 提升 ≥ 0.02 或 selected gain 提升 ≥ 0.05 pp；否则 A 组 NO-GO。
- Stage 2 → 3：mean ΔAUC（vs A0）≥ +0.01，没有 episode 的 ΔAUC < −0.03，且 ΔFinal ≥ −0.01。

## B. 空间表示 A/B：8³ 块与 Ray32（需要训练）
### B.0 前提：先补一个公平的参照模型 U0
目前没有一个模型与 B2 只差架构（TRAINING_COMPARISON §4）。所以 B 组必须在**同一训练配方**下训练所有变体，包括 8³ / Ray32 的参照模型（U0）。不能直接与 B2 或 V4 的历史数字比较。

**建议配方（四选一，需要你决定）**：

| 配方 | 内容 | 优点 | 缺点 | 单模型估计（4 × L40S） |
|---|---|---|---|---|
| **R-out**（推荐先做） | 只室外 Train-6 去 S-c，D100，从零 40k，lr 2e-4（与 V4 相同） | 与 V4、V3.1 同口径；V4 历史实测约 4.3 h | MP3D 只能零样本 | 8³：约 4–5 h；4³：估计 8–15 h【假设】 |
| R-mix | MP3D 228 + Macarons++ 138 条轨迹，D100，从零 40k，lr 1e-4（V3 的数据口径） | 两个域都训练 | 更慢；与 V3 的 TSDF 输入仍不同 | 约 6–10 h【假设】 |
| R-B2 | 复刻 B2 链：60k 室外 + 20k 混合，D100 | 最接近 B2 | 两阶段，最贵 | 约 12–16 h【假设】 |
| R-ft | 从 V2-Mix EMA@17.5k 在 D100 上微调（E2 配方） | 便宜 | 只能测“不改权重形状”的变化；**4³ 和 Ray64 会改变表示或 fc 形状，不公平** | — |

### B.1 建议矩阵（2 × 2 因子 + 可选）
| 编号 | 块 | 射线采样 | 需要的代码改动 | 需要的数据重建 |
|---|---|---|---|---|
| S0 = U0 | 8³ | 32 点均匀 | 无 | 无（复用 E2 D100 分片） |
| S1 | **4³** | 32 点均匀 | `fv/geometry.py:220` 的 block 和所有调用方、`fv/model.py:15 BLOCK` 一起改，**并加一致性断言**；建议给 model_cfg 加 `block` 键 | **全部分片的粗网格都要重建**（需重新回放 P1：t11_build / t21_build / e2_build），耗时待估 |
| S2 | 8³ | **64 点均匀** | `model_cfg.ray.n_points = 64`（`rays.fc` 变为 (64, 1024)） | 无 |
| S3 | 4³ | 64 点均匀 | S1 + S2 | 同 S1 |
| S4（可选） | 8³ | 32 点**对数间距**（近处密） | `points()` 加间距选项；V4 的 RayXAttn 写死了 `t_j`，本组不涉及 V4 | 无 |

**依据**：
- 【实测】室内 32 点的间距约为 3.7–4.5 个 F0 格（30–36 细体素），室外为 0.9–2.6 格。所以 Ray64 或对数间距主要在检验【假设】“室内射线采样过稀”。
- 4³ 检验【假设】“8³ 的块内占比太粗”。

**评估**：与历史协议完全相同，即 G1 首中 / 多表面、G2 固定状态、G3（条件执行），P1 模式为 b2。

**成本与资源**：
- 2 个模型可以并行（4 + 4 卡，每用户配额 8 卡）。
- S0 / S2 / S4 不需要重建数据。S1 / S3 要先重建粗网格分片，并量一次 4³ 的显存（编码器体素约多 8 倍）。

**建议顺序**：
1. 先跑 S0 和 S2：不需要重建数据，可以先回答“采样点数是否重要”。
2. 再决定是否重建 4³ 数据并跑 S1 / S3。
