# REFRESH_PROTOCOL — EXP Temporal Refresh（R10 / R5 / R2 / R1）

- **版本**：v1.0，2026-11-03 冻结，写于任何结果之前。
- **来源**：用户 2026-11-03 的夜间指令 Stage 1；审计依据为 `experiments/exp_model_diagnostics/REFRESH_AUDIT.md`。
- **评估场景**：非盲。

## 1. 问题与唯一自变量
**问题**：闭环中 P1 每步更新，但 3D 编码特征 h（F0 / F1）只在 t % 10 == 0 时重算，最多落后 9 步。更频繁地重新编码当前地图，能否改善未来深度预测、相机排序和覆盖？

**唯一自变量**：编码器刷新周期 R ∈ {10, 5, 2, 1}。

**保持不变**（用户要求第一轮严格隔离）：
- 室内规划区域：仍在 t % 10 == 0 时以当前相机为中心重建，并在新区域内重建 P1。
- Flow 噪声：仍是 R10 的配对规则，种子键用 t_r = 10⌊t/10⌋；所有 R 每一步都用同一组 K = 4 噪声。
- P1 每步融合真实深度。候选、DistP1、K = 4、10 步 Euler、Greedy-NV / 选择规则、GT 覆盖都不变。
- P1 协议固定为历史 B2 / E2 的 b2 模式：D100 推理 + S10 评分，与 Density A/B 的改动无关。
- 模型：B2（V2-Mix EMA@17.5k，sha 343f41ab…）和 E2-D100（EMA@5k，sha 61439612…）。V4 / V5 本轮不做。
- 不训练，不改架构。

## 2. 实现（`scripts/tr_refresh.py`，只在新进程里打补丁，不修改历史文件）
- **R = 10**：不打任何补丁，即历史代码。
- **室内**（`t06_planner.Planner.step`）：
  - t % 10 == 0：原 `refresh()` 不变（区域、P1 重建、编码、噪声）。
  - t % R == 0 且 t % 10 ≠ 0：用本步打分所用的同一个 geometry（R10 区域内记录 0..t 的 P1）重新编码 h，其余不变。
- **室外**（`v2_planner.main`）：
  - `refresh_time(t) = R⌊t/R⌋`；
  - `seed_key` 的 t_r 改为 10⌊t_r/10⌋，使每次（中间）刷新生成的噪声与 R10 逐位相同。
- **成本**：R1 每步多一次编码，室内还多一次粗网格计算。
- 历史训练时的陈旧增强覆盖 Δ ≤ 9 步，所以 R1–R10 的陈旧程度都在训练分布之内。

## 3. 固定状态 G1 / G2（`scripts/tr_fixed.py`）
- **状态集**：与 e2_fixed / Density A/B 相同，MP3D VALSEL 90 个状态 + Macarons++ Dev-3 275 个状态；区域、噪声、回放规则也相同。
- **方法**：
  - 对状态 t 和周期 R，编码器输入是 τ_R = R⌊t/R⌋ 时刻的 D100 粗网格（同一个 r10 区域）；
  - τ_10 = r10，就是历史做法；τ_1 = t，即当前地图。
  - 所有 R 都对同一个当前 geometry、同一组候选、同一组噪声打分，只有 h 不同。
- **回归要求**：R10 的分数和 pred_groups 与历史 e2_fixed 行（B2、D100）逐位相等，否则 STOP。
- **G1 指标**：
  - D100 UNKNOWN 射线上的首中深度 MAE、首中 / 无中准确率、漏报率、准确首中率；
  - 真实新子集；
  - 按 R10 陈旧度 s = t % 10 分组的误差曲线。
- **G2 指标**：Top-1、选中增益（pp）、Spearman；regret 放附录。另外统计相对 R10 的选择改变比例。
- **重点**：早期（前 20% 步数）。
- **统计**：沿用 Density A/B 的层级均值与场景级 bootstrap；室内另给房屋级，室外另给 episode 级。室内、室外分开报告。
- **成本**：编码时间、单步打分时间、峰值显存。

## 4. 闭环 G3
- **协议**：与历史 G3 相同。
  - MP3D：10 个 episode × 150 步；
  - Macarons++：30 个 episode（Dev-3 + Test-3）× 100 步。
- **R10**：直接复用历史 B2 / E2-D100 的 G3。前提是：
  - 新包装在 R = 10 下重跑 2 个 episode（B2 的 MP3D 2azQ1b91cZZ_L0_S60、E2D 的 Macarons++ colosseum_s0），与历史逐位相同；
  - 此外，R10 包装本身就是不打补丁的历史代码。
- **运行顺序**：R2、R1（B2、E2D）优先；R5 在资源允许时补跑。
- **调度**：沿用 Density A/B 的 queue3 调度规则（每 GPU 最多 1 个 MP3D episode，失败从头重跑）。
- **指标**：AUC@150 / @100、Cov@20、Cov@50、Final、每步决策时间、峰值显存、重访率、MP3D 停滞；场景级配对 bootstrap，含胜 / 负。
- **归因**：如果 R2 / R1 有收益，用 G1（预测）、G2（排序）和 G3 轨迹差异分别判断收益来自哪里。闭环差异不直接归因于单步预测。

## 5. 判定措辞
- 不预设阈值、不做事后调参。只有 CI 不含 0 才称“确定”；方向一致但 CI 含 0 称“趋势”。
- 负结果完整保留。
