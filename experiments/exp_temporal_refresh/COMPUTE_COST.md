# COMPUTE_COST — 刷新周期的计算成本

## 1. 编码器开销（实测）
| 来源 | 室内 | 室外 |
|---|---|---|
| 固定状态：单次编码器前向（每个模型） | 0.018 s | 0.007 s |
| 闭环：中途只重新编码一次（含同步） | 0.037–0.042 s | 0.019–0.026 s |
| 闭环：R10 完整刷新（区域重建 + P1 重放 + 编码） | 0.53–0.57 s，每 10 步一次，与 R 无关 | 编码 0.02–0.03 s |
| 每 episode 的额外编码次数 | R5：+150（10 个 episode 合计）；R2：+600；R1：+1350 | R5：600；R2：1500；R1：3000（30 个 episode 合计，含 R10 时刻） |
| R1 每步额外耗时 / 每步决策时间 | 约 0.04 s / 约 4.6 s（**< 1%**） | 约 0.02 s / 约 1.5 s（**约 1%**） |

**已证实**：R1 的编码器成本可以忽略，因为每步打分本来就要构建当前地图的粗网格，重新编码只多一次编码器前向。

## 2. 每步决策时间与峰值显存
| 配置 | 室内每步 | 室外每步 |
|---|---|---|
| B2 R5 / R2 / R1 | 4.57 / 4.65 / 4.78 s | 1.51 / 1.56 / 1.61 s |
| E2D R5 / R2 / R1 | 4.42 / 4.53 / 4.62 s | 1.44 / 1.53 / 1.50 s |
| 历史 R10（B2 / E2D） | 2.57 / 4.75 s | 2.00 / 1.61 s |

- 新跑的 R5 / R2 / R1 是在同一批次、同样负载下运行的（8 个 worker 共享 4 张 GPU），彼此可比：R1 比 R5 多约 0.1–0.2 s。
- 历史 R10 是在其他负载下运行的，**墙钟时间不能跨批比较**。
- 峰值显存：固定状态评估中刷新周期不改变峰值。闭环各配置的峰值见 `results/g3_summary.json`（peak_gb）。
