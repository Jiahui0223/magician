# G1_G2_RESULTS — 刷新周期的固定状态结果（B2、E2-D100 × R10 / R5 / R2 / R1）

- **协议**：REFRESH_PROTOCOL §3。所有 R 都使用 D100 推理 + S10 评分，同一组当前几何、候选和噪声，只有编码时刻不同。
- **回归**：365/365 个状态的 R10 分数与 pred_groups 都与历史 e2_fixed 逐位相等（1460 项检查）。
- **数据**：`results/fixed_summary.json`、`results/fixed_states.csv`；原始输出在 `work_dirs/exp_temporal_refresh/fixed/`。

## 0. 状态集合的限制（已证实）
- 两个状态集合的所有状态都满足 **t % 5 == 0**：
  - VALSEL：陈旧度 0 的 45 个，陈旧度 5 的 45 个；
  - Dev-3：陈旧度 0 的 133 个，陈旧度 5 的 142 个。
- 因此在这些状态上：
  - **R5 与 R1 的编码完全相同**（τ5 = τ1 = t），两者数值也完全相同；
  - R2 在奇数 t 上只落后 1 步；
  - 陈旧度为 0 的状态上四种 R 完全相同。
- **固定状态实际比较的是“当前编码”vs“落后 5 步的编码”（R10），以及“落后 1 步”（R2）。** R5 与 R1 的区别只能由闭环 G3 回答。
- 这是已有状态集合的性质（它们是历史上按 t 采样的），不是协议偏差。

## 3. 计算成本（固定状态测得）
- **单次编码**（只算编码器前向）：室内 0.018 s，室外 0.007 s。粗网格在每步打分时本来就要构建，所以 R1 每步额外开销约 0.01–0.02 s，相对每步 0.5–5 s 的决策时间可以忽略。
- 每状态的打分时间与 R 无关（约 0.53–0.60 s / 状态 / 模型）。
- **峰值显存**：室内进程 17.9 GB、室外 8.0 GB（两个模型、两张地图同时在显存中），与 R 无关。
- 闭环实测成本见 COMPUTE_COST.md。
