## 0. 一页摘要

**要回答的三个问题**（计划书 §12）：
1. V2 是否比完整世界生成快？
2. 在同一协议下，Coverage / AUC 能否保持或提高？
3. U 是否比 DistP1 更有用，或者两者互补？

**V2 做什么**：不生成完整的 3D 世界。对每个合法候选相机，直接预测这个视角下 K 个可能的"第一层可见表面"深度和命中情况，再用冻结的 DistP1 和 Greedy 选动作。

**与 EXP4 的关系**：

| 部分 | 来源 |
|---|---|
| 传感器、114×64 打分射线、P1 融合、合法动作和碰撞过滤 | 全部复用，不改 |
| DistP1 的去重与权重、选择和回退规则 | 全部复用，不改 |
| 规划器子进程协议、GT 隔离守卫、公共评估器 | 全部复用，不改 |
| 候选视角的确定性几何投影 | **新增** |
| 共享观测编码器 + 2D 条件 flow 网络 | **新增** |
| 由预测深度计算 DistP1 的入口 | **新增**，下游与冻结代码共用 |

**训练数据**：只用室外 Train-6（data/macaronspp_belief/v1 的 180 条轨迹、18,180 个状态，每步都记录了合法动作）。标签是 Train-6 GT 网格上候选视角的真实第一命中深度。Dev 只用于评估。

**闭环实验**：Dev-3 × 5 个起点 × 100 步，共 5 组实验：V2G-R10（主）、V2G-Native、V2U、V2GU、V2G-K1。基线 B0 和 MAGICIAN 引用已冻结的结果，不重跑。

**粗估成本**：数据和标签约 5 GPU-h，训练 10–20 GPU-h，诊断约 5 GPU-h，闭环 20–35 GPU-h。

**最大风险**：只有 6 个训练场景，而 V2 从零训练，没有 Seen2Scene 的先验。

## 4. 输入：候选视角的确定性几何投影（Task 1.1）

### 4.1 射线
- **规划时**用冻结的 114×64 打分射线（4×4 像素块中心），这样 DistP1 的射线与 B0 完全相同。
- **训练时**给整个射线网格加一个随机的亚像素平移，范围 [−2, 2) 像素，每个样本一个、带种子。这样模型对网格位置不敏感，评估时就可以在 G1 的整数像素射线 (4j+2, 4i+2) 上查询，与 G1 的未来深度 ES 逐条射线比较（见 D4）。

### 4.2 每条射线的投影
用 SceneCaster 同样的步进方式（半体素、同一个域），沿射线读取当前 P1 状态：

| 量 | 定义 |
|---|---|
| `t_known` | 已观测 BAND 的第一个交点。用 SceneCaster 在"只有观测"的投射体上求得，与 B0 投射中的"已观测命中"逐位相同。没有交点时为 ∞。 |
| UNKNOWN 段 | 在 `t_known` 之前、域内的 UNKNOWN 区间，可以不止一段。 |
| `L_u` | UNKNOWN 段的总长度（"未知弧长"）。 |
| `d_lo` | 第一次进入 UNKNOWN 的位置。 |
| `t_cap` | 量程上限：70 / dz / k_M。 |
| 域的进入 / 离开 | 射线进入和离开表示域的位置。 |

每条射线据此归为三类：

| 类别 | 条件 | 结果 |
|---|---|---|
| **M_known** | 第一个事件就是已知表面 | 结果确定，等于 `t_known` |
| **M_empty** | 一路都是 EMPTY 或域外，直到离开域 | 结果确定，域内没有命中 |
| **M_unknown** | 在 `t_known` 之前经过至少一个 UNKNOWN 体素 | **需要预测** |

**遮挡**：步进到第一个已知表面就停止，所以墙后的 UNKNOWN 不会被当成 EMPTY，也不会被算进可预测范围。

### 4.3 输入通道
每个候选一张 [C_p ≈ 10, 64, 114] 的图：
- 射线类别（3 个 one-hot 通道）；
- `t_known / t_cap`、`d_lo / t_cap`、`L_u / t_cap`；
- UNKNOWN 段的数目（截断到 3）；
- 射线在世界坐标中的仰角；
- 相机高度（相对场景框，归一化）；
- `t_cap`（以模型单位表示的量程）。

z0 只用于打分，不作为输入。

### 4.4 信息量与 B0 相同
- V2 **只读 P1 状态和位姿**。B0 的生成器也只读 P1 状态，所以两者看到的观测信息完全相同。
- 服务记录里虽然有完整的历史深度，但不额外输入。否则"架构的变化"会和"信息量的变化"混在一起（见 D3）。
- P1 的 BAND 来自 10% 采样，比较稀疏，已知表面之间会有空隙；空隙处表现为表面前的薄 UNKNOWN 层。V2 需要学会"EMPTY 边界后面紧接着就是表面"。B0 的生成器面对的是同样的情况。

## 5. 训练标签（Task 1.1，只用 Train-6 的 GT）

### 5.1 标签怎么来
- **取哪些状态和候选**：对每个 Train-6 状态 (轨迹, t)，取 L1 记录里的全部合法候选。
- **怎么求标签**：在 GT 网格（运行单位，OBJ × 10）上，沿该候选的 7,296 条射线（含 §4.1 的亚像素平移）做精确的射线–三角形求交，用 magician 环境里的 trimesh + embree（已确认可用）。
  - 正反面都算，与 PyTorch3D 渲染器不剔除背面一致。
  - z = t · dz：
    - z < 0.5（近裁剪）的射线标为无效；
    - z ≥ 70 记为无命中。
- **转换成 V2 的目标**：
  - `n` = 真实第一命中是否落在 UNKNOWN 段内，并且在 `t_known` 之前（容差 1 体素）。
  - `s` = 该命中在未知弧长上的位置比例 ∈ [0, 1)；只在 `n = 1` 时有定义。
  - 真实命中如果落在已观测 EMPTY 里，这条射线**不可行**：说明 P1 雕错了，即已知的薄结构 H5 效应。这类射线不进损失，逐样本记录比例。
  - 真实命中在域外：如果它在域内 UNKNOWN 段之前，就视为遮挡，`n = 0`。
- **不读的东西**：GT 覆盖率、`sim_meta.json` 的诊断字段、Dev 场景的任何文件。由清单检查和守卫保证。

### 5.2 标签校验（在训练之前，阈值在 T1.1 冻结时写死）
- **与渲染器对照**：每个状态实际执行的那一个候选，用 embree 在整数像素上求交，结果与 L1 记录中下一帧 PyTorch3D 的 zbuf 比较：
  - 报告非轮廓像素的命中一致率和相对深度误差；
  - 轮廓像素单独统计。MAGICIAN 的反投影约定与光栅化的像素中心有微小差异，P1 本身也接受这一点。
- **合成测试**：已知平面、盒子和遮挡物的网格。

### 5.3 规模、存储和采样
- **规模**：18,180 个状态 × 约 7.5 个候选 ≈ 13.6 万个候选视角，约 10 亿条射线。embree 在 CPU 上需要几个小时。
- **存储**：约 25–30 GB（投影通道 fp16 + 标签），另有粗体素约 5 GB，放在 `work_dirs/exp5_future_view/task1/data/`。
- **采样权重**：Task 0 原本应提供低覆盖区间的权重，但 Task 0 未完成。这里事先固定为"每个 (轨迹, t) 等权，t ≤ 20 的状态权重 × 2"，保证极稀疏的早期状态有足够样本。这个规则不读 GT 覆盖率。

## 6. 模型（Task 1.2）

```text
P1 状态（场景网格 X×Y×256，三态）
  └─ 每 8³ 统计一次 → 粗体素 [4, X/8, Y/8, 32]（EMPTY / UNKNOWN / BAND 比例 + 域内比例）
       └─ A. 共享编码器（3D CNN，全卷积，可变场景尺寸）→ 特征体 h_t：[32, X/8, Y/8, 32] + [64, X/16, Y/16, 16]
每个候选 a（M 个，3–10）：
  B. 确定性投影（§4）→ C_a：[C_p, 64, 114]
     射线特征：沿每条射线在 h_t 上取 N = 32 个点（三线性）→ 沿射线做 1D 卷积 → [64, 64, 114]
  C. 2D 条件 flow U-Net：输入 x_τ [2, 64, 114] ⊕ C_a ⊕ 射线特征 ⊕ τ 嵌入 → 速度 [2, 64, 114]
     K 个噪声 ε_k ∈ R^{2×64×114}，10 步 Euler → (n̂, ŝ)
  D. 解码（确定性）：
     - n̂ > 0 → t̂ = 未知弧长上 ŝ 处的位置（一定落在 UNKNOWN 段内）；
     - n̂ ≤ 0 → 结果由投影决定（命中 t_known，或无命中）；
     - M_known / M_empty 射线直接用投影值覆盖。
     输出：深度 D̂ [M, K, 64, 114]（射线距离，模型单位；另存 z 深度，运行单位）、命中 Ĥ [M, K, 64, 114]
  E. 批处理：h_t 只算一次；所有候选 × K 一次成批采样
```

**规模**：编码器约 1–2M 参数，射线模块约 0.2M，U-Net 约 15–25M。实际数字以 T1.2 的 `architecture.md` 为准。

**设计理由**：
- **输出直接定义在 DistP1 的 114×64 射线上**：DistP1 只读这些射线，更高分辨率没有用处。
- **"未知弧长"参数化**：
  - 预测的命中**按构造**不可能落在已观测 EMPTY 里，也不可能在已知表面之后。这等于一个硬性的已知几何约束。
  - 这是计划书 §9.2 允许的"硬投影"。它不会锁死本该 UNKNOWN 的区域：UNKNOWN 段内哪里都可以命中，也可以不命中。
  - 天空、超出量程、离开域的射线不会被预测成墙，因为"不命中"是一个独立的结果。
- **共享编码器**提供视锥以外的上下文，比如墙在别处的延续。投影提供视锥内的精细几何。
- **在像素空间做 flow**（每个视角只有 2×64×114 个数），没有单独的 view latent。因此 `U_latent` 记为"不适用"，并写明原因。

**考虑过但不采用**：
- **每条射线独立的类别分布**：射线之间没有联合一致性，会扭曲"唯一新体素"的计数和分歧。
- **256×456 全分辨率输出**：DistP1 用不上。
- **以原始历史深度为输入的编码器**：信息量多于 B0，造成混杂。可以以后作为单独的变体。

## 7. 训练（Task 1.2）

### 7.1 损失
- 条件 flow matching（rectified flow）的速度 MSE：
  - `n` 通道作用在全部 M_unknown 且标签有效的射线上；
  - `s` 通道只作用在 `n = 1` 的射线上。`n = 0` 时 `s` 的目标填 +1，但不计损失。
  - 确定的射线和无效射线不进损失。
- **不**对 K 个输出各自施加同一张 GT 的 L1。

### 7.2 让同一个 checkpoint 同时支持 R10 和 Native
- 训练时以 0.5 的概率让编码器的输入取较早的状态 t − Δ，Δ 在 1–9 中均匀取值；其余情况 Δ = 0。
- 投影和标签始终来自当前状态 t。
- 这正好对应推理时 R10 模式下编码器特征最多旧 9 步的情况（§10.2）。

### 7.3 优化（事先固定，不搜索）
- AdamW，lr 2e-4，余弦退火，预热 1k 步；
- batch = 64 个候选视角（约 8 个状态 × 8 个候选）；
- 60k 步，bf16，EMA 0.999，seed 0；
- 每 5k 步存一次。**最终 checkpoint 预先定为 60k 步的 EMA**，不用 Dev 挑选。

### 7.4 冒烟阶梯（每一级都过了才进下一级）
1. 数据和几何单元测试（§11）。
2. 单 batch 过拟合：损失降到接近 0，采样能复现标签。
3. 梯度检查：没有 NaN，每个模块都收到梯度。
4. 单相机采样检查：K 个样本在 M_unknown 射线上各不相同，在确定射线上完全相同。
5. 2k 步短训练，然后检查下列退化。

### 7.5 STOP 条件（在 Train-6 留出集上判定，事先写定）
出现以下任何一项都停止，报告原因，**不进入闭环**：
- **坍缩**：M_unknown 射线上 K = 4 个样本的平均两两分歧 < 1%。
- **深度退化**：ŝ 在射线之间的标准差 < 0.01，即所有射线几乎预测同一个位置。
- **命中率失真**：预测的"新命中"比例与标签的比例之比不在 [0.5, 2] 内，包括把无命中预测成墙的情况。
- **数值问题**：出现 NaN / Inf。

"不如简单基线"（§9 的 Frontier 启发式）**不是** STOP 条件，只如实报告。计划书 §11.2 要求：V2-G 只要正确性通过就按协议执行。

### 7.6 成本
- 每个训练约 5–10 GPU-h（L40S，估计）。
- 泛化探针再加一个训练。
- 训练日志、checkpoint 和 sha 都放在 `work_dirs/exp5_future_view/task1/training/`。

## 8. 打分（Task 1.3）

### 8.1 DistP1(a)：语义固定
- 新增一个入口 `new_set_from_depth(caster, rays, t̂, Ĥ, dz, z0)`：把 SceneCaster 投射得到的命中换成 V2 的预测命中，其余代码路径照旧：
  - 场景网格线性索引；
  - 只算域内命中；
  - z ≤ 70；
  - 用 `band_dil` 判定"新"；
  - 唯一体素去重，权重取最大值，分数取 K 个样本的平均。
- **逐位等价测试**：把某个 T1-C 世界经 `caster.cast` 得到的 (t, hit) 输入新入口，要在 73 个状态的全部候选上逐位复现 `abl_score.new_set` 的 ids 和 weights。
- **选择规则**：沿用 `choose`。NaN 视为 INVALID，停止受影响的运行。

### 8.2 U(a)：同一个相机下 K 个预测之间的分歧
**主定义 U_new**（预注册，在任何 Dev 结果之前冻结）：

> 对候选 a 和射线 r，设 e_k(r) ∈ {0, 1} 表示样本 k 在 r 上有没有 DistP1 意义下的"新"命中（域内、z ≤ 70、3³ 邻域内没有已观测 BAND），t_k(r) 是它的射线距离。
> - 两两分歧 d_ij(r) 的取值：
>   - e_i ≠ e_j：取 1；
>   - 两者都命中：取 min(1, |t_i − t_j| / δ)，δ = 2 体素；
>   - 两者都不命中：取 0。
> - c(r) = d_ij(r) 对 i < j 的平均。
> - w(r) = min(1, (z̄(r) / z0)²)，与 DistP1 的距离权重相同。
> - **U_new(a) = (1 / 7296) · Σ_r w(r) · c(r)**，分母是固定的射线数，与 P2 相同，不重新归一化。

只有 M_unknown 射线的 c 可能大于 0：确定射线在 K 个样本之间完全相同。

**辅助诊断**（只报告，不进入闭环）：
- `U_hit`：w · 4p(1 − p) 的平均，p 是 K 个样本中有新命中的比例；
- `U_depth`：都有新命中的样本对之间截断深度差的平均；
- `U_gain`：K 个样本各自 DistP1 分数的标准差；
- `U_latent`：不适用（像素空间 flow），记录原因。

**与 P2 的数学区别**（计划书要求明确写出）：

| | P2（EXP4 T3） | U_new（V2） |
|---|---|---|
| 样本来源 | K 个完整世界的投射 | K 个以候选相机为条件的视角样本 |
| 计入的事件 | 任何第一命中，包括生成在已观测 EMPTY 中的表面（占 P2 分歧的 15%） | 只计 DistP1 意义下的新命中；按构造不可能落在已观测 EMPTY 中 |
| 射线范围 | 全部 7,296 条，配合门控和近平面规则 | 实际只有 M_unknown 射线可能产生分歧 |
| 权重 | 不加权 | 与 DistP1 相同的距离权重 |

**如实说明**：U_new 仍然属于"深度分歧"这一族（VHD / P2）。上面这些改动去掉了 P2 已知的一部分无用分歧，比如 EMPTY 区和不可观测的射线，但"已知几何前面的错误几何"（占 P2 的 23%）仍可能出现。

本轮的检验问题是：**在硬约束下、以视角为单位的样本分歧，能否成为有用的规划信号**。U 不等于期望信息增益，只表述为"预测的可观测分歧"。

### 8.3 GU：DistP1 与 U 的组合
- **分数**：GU(a) = rank(DistP1)(a) + λ · rank(U_new)(a)。rank 是在同一状态的候选之间、把排序归一化到 [0, 1]，并列取平均。
- **λ 的选择**：从 {0, 0.25, 0.5, 1, 2} 中，在 **Train-6 留出集的校准状态**上，按"对真实一步增益的平均遗憾最小"选取，并列时取较小的 λ。
  - 真实增益用冻结的 `m_gain_eval`，在 MAGICIAN 环境中计算。这只在训练场景上使用 GT，属于合法的校准。
  - 约 360 个状态（留出轨迹 × t ∈ {0, 1, 2, 3, 5, 10, 20, 30, 50, 70}），约 1–2 GPU-h。
- **结果映射**：
  - 如果选出 λ = 0，GU 就等于 G，**V2GU 不运行**，报告中写明原因。
  - 如果 U 在 > 50% 的状态上对所有候选取同一个值，或者出现非有限值，U 判为无效，V2U 和 V2GU 标为 FAIL，V2G 照常进行。
- λ、归一化方式、有效区域、无命中的处理和 U 的定义，都在任何 Dev 的 100 步结果出现之前冻结，之后不改。

## 9. 固定状态诊断（Task 1.3，只描述，不做选择）

| 状态集 | 内容 | 用途 |
|---|---|---|
| **S-a** | Dev-5 的 73 个 T5-D A1 状态，有真实增益；其中 48 个有 G1 未来帧 | 与 B0 和冻结世界做一步排序比较；未来深度 ES 与 G1 的数值直接可比 |
| **S-b** | Dev-3 的 B0 闭环状态，1,500 个 | 在**同一批状态**上比较 V2 与 B0 的排序，这是反事实的一步比较 |
| **S-c** | Train-6 留出集，约 360 个 | λ 校准；泛化探针 |

**在同一批状态、同一个合法列表上比较的方法**：
- V2-DistP1（K4；K1；K16 只用于校准诊断）；
- V2 的 U 系列；
- **Frontier 启发式 + DistP1**：不学习，假设每条 M_unknown 射线在 `d_lo` 处命中。作为"V2 学到了什么"的下限对照。
- **真实深度 + DistP1**：只在评估侧计算，作为上限，用来把"DistP1 本身的排序损失"和"预测误差造成的损失"分开。
- B0（T1-C 世界）和冻结世界上的 DistP1：引用已归档的分数。

**指标**：
- 排序：Spearman、top-1、遗憾、false promise、dead share。
- 深度：在 G1 未来帧的整数像素射线上算 fair ES、CRPS、命中 Brier、false confidence，与冻结世界的 62.77、T1-C 的 59.74 同口径。
- 校准：PIT 直方图、命中概率的可靠性曲线（用 K16）。
- 多样性和坍缩。
- **跨视角一致性**：同一状态里两个候选的视锥有重叠时，比较同一个 k 与不同 k 的重投影一致率。这只是诊断，用来检查"共享噪声"有没有带来假设的同一性。
- 分层：场景、t、覆盖率、距离。

**耗时**：
- 分项测量：编码器、投影、M×K 采样、打分，以及峰值显存和吞吐。
- 全部在 L40S 上测。B0 的耗时如果不是在同型号 GPU 上测的，就在 L40S 上对 3 个状态各重跑一次 `generate_refresh`，**只计时，不产生新结果**。

**目的**：确认可以合法闭环，并定位失败原因。不替代最终的 Cov / AUC，也不设性能门槛。

## 10. 闭环验证（Task 1.4）

### 10.1 公共规则（与 abl_2 相同）
- Dev-3（barts、pantheon、colosseum）× 5 个起点，100 步，记录 101 个覆盖率值。
- 模拟器、合法动作、碰撞过滤、并列和回退规则、公共评估器都不改。
- GT 只用于碰撞过滤和独立的评估器。V2 子进程装 LeakGuard，读取服务记录时经过白名单检查。
- **续跑**：从服务记录重放 P1，噪声按种子重建，不需要保存世界文件。续跑后的结果必须与不中断的运行逐位相同。
- **t = 0 的差别**：colosseum s2 在 t = 0 时没有 BAND。B0 当时没有世界，只能随机回退；V2 不需要 BAND 也能预测。这是架构本身的差别，会在报告中单独标出。

### 10.2 两种刷新模式（计划书 §11.3：把"架构变化"和"刷新更频繁"分开）

| 项目 | R10（与 B0 匹配） | Native |
|---|---|---|
| P1 观测状态 | 每步更新 | 每步更新 |
| 候选投影 C_a | 每步更新 | 每步更新 |
| 编码器特征 h | 只在 t = 0, 10, …, 90 更新 | 每步更新 |
| 噪声 ε_k | 只在 t = 0, 10, …, 90 重新抽取 | 每步重新抽取 |
| 模型权重 | 冻结 | 冻结 |

- **噪声种子**：`seed_world("exp5-V2/<scene>/s<start>", rep, t_r, k)`，t_r 是最近一次刷新的时刻。同一次决策里所有候选共用 ε_k（common random numbers，降低候选之间比较的方差），**不**声称这带来跨视角的几何一致性。
- **无法消除的混杂**：B0 的 K 个世界在 10 步内是持久的三维假设；V2-R10 只让编码器特征和噪声保持不变，视角样本每步都重新生成。报告中如实写明。

### 10.3 实验组

| ID | 模式 | K | 评分 | 优先级 | 回答的问题 |
|---|---|---|---|---|---|
| **V2G-R10** | R10 | 4 | DistP1 | 1（主） | 新架构能否以更低成本支持同等 Cov / AUC（与 B0 刷新匹配） |
| **V2G-Nat** | Native | 4 | DistP1 | 2 | V2 自身的刷新频率效应（与 V2G-R10 配对） |
| **V2U-R10** | R10 | 4 | U_new | 3 | 只靠预测分歧选点是否有效 |
| **V2GU-R10** | R10 | 4 | rank DistP1 + λ·rank U | 4（λ > 0 时才跑） | 分歧有没有额外的规划价值 |
| **V2G-R10-K1** | R10 | 1 | DistP1 | 5（诊断） | V2 自身的 K1 对 K4（成本和稳定性） |

- **重复**：每组每个起点 3 个噪声重复（rep 0–2）。先在起点内取平均再做配对，重复不算独立场景。V2 的轨迹很便宜，这样还能估计 B2 当时无法估计的噪声方差。
- **基线**（引用冻结结果，**不重跑**，记录哈希）：

  | 基线 | Cov@100 | AUC@100 | 说明 |
  |---|---|---|---|
  | B0 = abl_1 A2 | 0.866 | 0.683 | |
  | MAGICIAN T7a | 0.868 | 0.697 | 多步搜索，与我们的 Greedy 不同 |
  | B2（K1） | 0.867 | 0.675 | |
  | B1（Frozen） | 0.862 | 0.693 | |

- **运行顺序**：10–12 步冒烟 + 续跑一致性检查 → V2G-R10 → V2G-Nat → V2U-R10 → V2GU-R10 → V2G-R10-K1 → 分析。
- **每组都报告**（计划书 §11.4）：
  - Cov@100、AUC@100、Cov@10 / 20 / 50、101 点曲线、15 个起点的逐条表；
  - 与 B0、MAGICIAN 的配对差：15 个起点 bootstrap，10,000 次，seed 0，95% CI；
  - 一步排序诊断（Spearman、top-1、遗憾、false promise、零增益步数）、观察距离分布；
  - 每步决策的分项耗时、每条轨迹的墙钟时间和 GPU-h、峰值显存、续跑开销；
  - 完整性：评估器重放逐位一致、全部动作合法、守卫没有拒绝。
- **统计口径**：只有 3 个独立场景，结论都是探索性的。不根据结果剔除轨迹。
