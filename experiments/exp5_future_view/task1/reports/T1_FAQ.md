# Task 1（V2）问答：候选视角、损失、训练步数，以及"为什么结果不差"（2026-10-26）

> 回答你 10-26 的问题。数字都来自 T1.1–T1.4 报告、`architecture.md`、`architecture_measured.md` 和 `configs/`，本文没有新的实验。

## 1. 候选视角有多少？
- **每一步的候选**：当前位姿的全部合法动作，也就是 MAGICIAN 网格上的相邻位姿（移动一格，或俯仰 / 方位转一档）。不增加、不删除，也不固定为 8 个。
  - 训练数据（Train-6）中平均约 7.2 个；
  - 闭环测试（Dev-3，V2K4 的 15 条 r0 episode）中为 2–10 个，平均 6.8 个，中位数 7 个。
  - 每个候选都打分，然后贪心选最高的那个。
- **每个候选视角怎么表示**：64 × 114 = 7,296 条射线，与 DistP1 打分用的射线逐位相同，是全分辨率 256 × 456 的 1/4。
- **训练数据**：
  - 180 条 Train-6 轨迹 × 每条 100 个状态 × 全部合法候选 = **129,914 个候选视角**，约 **9.5 亿条射线标签**；
  - 去掉留出的 42 条轨迹（S-c），训练集是 138 条轨迹、13,800 个状态、98,887 个视角；
  - 6 个训练场景是 bannerman、dunnottar、fushimi、liberty、pisa、redeemer。闭环测试的 Dev-3（barts、pantheon、colosseum）训练时**从未见过**。

## 2. 损失有哪些？
**只有一个损失**：rectified flow 的速度 MSE。

  L = ‖v̂(x_τ, τ, 条件) − (x₁ − ε)‖²，其中 x_τ = τ · x₁ + (1 − τ) · ε

**预测对象 x₁**：每条射线两个数 (b, y)：

| 量 | 含义 | 取值 |
|---|---|---|
| b | 有没有命中表面（有符号比特） | 命中 +1，不命中 −1 |
| y | 命中位置落在这条射线"未知段"的哪里 | 命中时为 2s − 1，s ∈ (0, 1) 是在未知弧长上的比例；不命中时为 +1 |

**哪些射线算损失**：

| 射线 | 是否算损失 | 原因 |
|---|---|---|
| 穿过未知区域、标签有效（命中 / 不命中 / 已知） | 算，两个通道同权 | 这是唯一需要预测的部分 |
| 只经过已观测区域（已知表面 / 已观测空） | 不算 | 直接用观测几何，不需要预测 |
| 标签无效（被框外物体先挡住、太近、不可行） | 不算，权重为 0 | 标签不可靠 |

**没有用的损失**：深度回归、分类交叉熵、跨视角一致性、感知损失都没有用。

**训练中只监控、不进损失的量**：
- 固定 τ 和噪声下的 FM 损失（训练集 / 留出集）；
- fair ES（能量分数，衡量 K 个采样的分布质量）；
- 假墙率、命中比例等 STOP 规则。

## 3. 训练了多少步？

| 项 | 值 |
|---|---|
| 步数 | **60,000 步**（预热 1,000 步） |
| 每步 batch | 64 个候选视角（8 个状态 × 每个状态最多 8 个候选） |
| 优化 | AdamW，lr 2e−4，余弦退火到 0，weight decay 0.01，梯度裁剪 1.0，bf16，EMA 0.999 |
| 数据量 | 60k × 64 ≈ 384 万个视角样本，约等于把训练集过了 39 遍 |
| 硬件和时间 | 4 × L40S，每步 0.25 s，约 4.7 小时，约 18.7 GPU-h |
| 参数量 | 24.8M：3D 编码器 2.41M + 射线编码器 0.08M + 2D flow U-Net 22.33M |
| 用于闭环的模型 | EMA 权重 @60k，冻结后不再调 |

**两个诊断模型**（不用于闭环）：
- LOSO：去掉 pisa 训练；
- 3 场景探针：只用 3 个场景训练。

它们只用来量化跨场景泛化。

## 4. 为什么一个单独训练的小模型，闭环结果能和 MAGICIAN 打平？

**先说准确的结论**：在 Dev-3 的 15 个起点上：
- V2K4 的 AUC@100 为 0.713，MAGICIAN 为 0.697，差 +0.016 [−0.011, +0.053]，**置信区间含 0，是打平，不是更好**；
- 最终覆盖率 V2 略低（0.856 对 0.868）；
- 在 colosseum 后期，MAGICIAN 更好（Cov@100 0.87 对 0.81）。

**能打平的原因**：

1. **V2 不需要是一个好的"世界模型"，只需要把每步约 7 个候选的大致顺序排对。**
   - 排序比重建容易得多。V2 的预测其实离完美很远：
     - 一步排序的 Spearman 只有 0.42–0.54，用真实深度时是 0.62–0.80；
     - 一步遗憾 0.58–1.21，用真实深度时是 0.09–0.22，相差 3–6 倍。
   - 但只要"最好的那几个"大多排在前面，贪心闭环就能走得不错。

2. **打分规则和 MAGICIAN 同源，这是很大一部分功劳。**
   - DistP1 用的距离权重 min(1, (d / z0)²) 与 MAGICIAN 的增益公式相同，z0 也取场景尺度的一半。
   - EXP4 消融已经发现：把打分换成 DistP1，B0 的最终覆盖率就追平了 MAGICIAN（0.866 对 0.868）。
   - 反过来，去掉距离权重（E3 U_raw），AUC 立刻掉到 0.611，ΔAUC −0.103，15 条里 14 条变差。
   - 另外，候选集合、模拟器、传感器和覆盖率评估都与 MAGICIAN 完全相同。
   - 所以 V2 的角色是：**用很便宜的方式，为 MAGICIAN 式的打分提供未知区域的深度**。

3. **硬约束去掉了最常见的失败方式。**
   - 解码规则保证预测的命中只能落在未知体素里，不会落在已观测的空区域里，也不会落在已知表面后面；已观测的部分直接用真实观测。
   - Task 0 室内的世界模型之所以停滞，正是因为在已观测的空区域里"幻想"出了增益；V2 按构造不会出现这种情况。

4. **V2 的优势集中在前期，恰好是 AUC 最看重的阶段。**
   - 第 10–40 步时未知区域最多。这一阶段 V2 的一步排序明显好于 B0：t = 1–20 时 Spearman 0.60–0.62，B0 为 0.36–0.40。
   - 覆盖曲线上，V2 在第 28 步领先 B0 约 0.10，在第 11 步领先 MAGICIAN 约 0.095；约 60 步后略低。
   - 原因有两个：
     - V2 每一步都根据最新观测重新预测，而 B0 的世界每 10 步才生成一次，中间是旧的；
     - 起点什么都看不到时（colosseum s2），B0 无法生成世界，V2 仍然能预测。

5. **监督很密，任务也很局部。**
   - 9.5 亿条射线标签，每条只问一件事："给定附近已观测的结构，这条射线在未知段里会在哪里撞到表面？"
   - 这种局部规律（墙会延续、地面会连续）在不同场景之间有一定共性，足以支撑排序。

**它的不足**（为什么说"还没那么好"）：
- **跨场景泛化弱**：pisa 整场景留出时，预测误差（ES）约为同场景留出的 5 倍；训练场景从 6 个减到 3 个时，没见过场景上的误差单调增大（8.3 → 41.7 → 58.4）。Dev-3 也是没见过的场景，所以预测质量其实不高，靠的是排序的鲁棒性。
- **规模小**：只有 3 个开发场景、15 个起点，Test-3 从未使用。
- **室内**（Task 0）：站点图上 V2 也能和 MAGICIAN 打平；但到了网格上，预测区域只有约 7.8 m 的问题就暴露出来了（T0.12-C）。
- **提升空间明确**：真实深度 + DistP1 的一步遗憾只有 V2 的 1/3–1/6，说明提高预测质量（更多训练场景、更好的跨场景泛化）还有很大空间。

**一句话总结**：结果不差，主要靠这个组合——"轻量的未来视角预测 + 与 MAGICIAN 同源的距离加权打分 + 只在未知区域预测的硬约束"，它在排序上已经够用。V2 本身的预测离真实还差很多，跨场景泛化是下一步最大的瓶颈。
