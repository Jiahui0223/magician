## 2. 总体思路

两个域用**同一个虚拟传感器**（456×256，竖直 FOV 60°，与室外相同）、**同一套 P1 融合**和**同一个评估器**，只换场景。

- 室内的相机位置和朝向都取自 MP3D 真实扫描站点，物理上一定合法。
- MP3D 的真实深度帧只用于几何校验，以及标出网格孔洞。
- 这样，室内外剩下的差别只有"场景几何 / 数据来源"和"尺度"两项，可以用对照组分开。

## 3. 阶段设计

### T0-A 授权与数据清点（只用 CPU）
- **最少需要三类 MP3D 文件**：
  - `house_segmentations`：网格，以及楼层和房间框；
  - `undistorted_camera_parameters`：每帧的内参和位姿；
  - `undistorted_depth_images`：真实深度，用于校验。
- 不需要彩色图、skybox 或 Habitat 包。Habitat-Sim 在 CentOS 7 / glibc 2.17 上安装困难，渲染改用现有的 PyTorch3D 管线。
- **划分**：官方建筑级 61 / 11 / 18（train / val / test）。
  - Task 0 只用 val 的 11 个；
  - test 的 18 个封存；
  - train 的 61 个留给 Task 1 的室内扩展。
- **输出** `dataset_manifest.csv`：scene id、楼层数、各层高度、站点数、帧数、网格面数、文件 sha。

### T0-B 几何审查（计划书 §3 的 6 项）
- **坐标变换链**：MP3D 的 z-up 米制 → 我们的 y-up 运行坐标 → 模型窗口坐标。
- **单元测试**：
  - 用已知几何检查投影和反投影误差；
  - z 深度和射线距离不能混用。
- **真实帧校验**：
  - 在真实相机位姿处用网格渲染深度，与真实深度逐像素比较。这一步验证位姿约定（c2w、相机前向轴）和网格质量。
  - 渲染深度明显比真实深度远的地方就是网格孔洞，用它生成 GT 无效掩码：这些表面不计入分母，从孔洞穿过去雕出的空区域也不当作可靠的 EMPTY。
- **室内量程**：按真实深度的统计确定，在看到任何模型结果之前冻结。
- **室外**：只复核已冻结并通过的 E-M2，不重做。
- **输出**：`geometry_validation.md`、测试和可视化。任何关键项失败都先修复，再评估。

### T0-C 低覆盖状态与覆盖区间支撑
- **室内尺度**：沿用 E-M2 的同一规则，k_I = max(1, 层高 / 2.816)，单层窗口；室内 k ≈ 1–1.3。
- **室内评估区域**：以起点站点为中心，最多 3×3 个窗口（约 7.3 m 见方），并裁剪到楼层框之内。这样窗口数和室外（1–14）在同一量级，成本也可控。
- **室内轨迹**（可解释的模拟轨迹）：
  - 从一个真实站点出发，按它真实的 18 个朝向逐帧拍摄；
  - 拍完再走到最近的未访问相邻站点（≤ 3 m，且网格上视线不被挡）。
  - 每一帧都是扫描仪真实站过的位置和朝向，没有瞬移。
- **室外轨迹**：MAGICIAN 回放轨迹，与 G1 同源。
- **覆盖率 C_obs**：
  - 在模型体素坐标下计算，两个域用同一份代码：
    > C_obs = |GT 表面体素 ∩ 历史观测 BAND 的 1 体素膨胀| ÷ |有效 GT 表面体素|
  - GT 用同一个传感器在一组密集位姿 Π* 上渲染、融合得到：室内 Π* = 全部真实站点位姿，室外用已冻结的 target-v2。UNKNOWN 和孔洞掩码都不计入。
  - 室外另外报告 MAGICIAN 官方覆盖率作为参照。
- **选状态的规则**（预注册，防止挑样本）：每条轨迹在每个区间只取"第一次进入该区间"的那一帧。
- 先出支撑表：每个区间、每个域各有多少独立场景和状态。两个域都有足够场景的区间才做对照，其余标"不可比"。然后冻结协议。

### T0-D 冻结模型诊断（GPU）
- **模型**：Frozen S0-F 对 T1-C@2000，各取 K4；K1 直接用第 0 个世界，不另外生成。10 步 Flow，256³ 窗口，种子约定与 G1 相同。
- **指标**（沿用 G1 的定义）：
  - 隐藏表面的 P / R / F@1 和 F@2（体素单位）；
  - 未来深度（轨迹之后的 10 帧）：ES、CRPS、命中 Brier、false confidence；
  - Q1 已观测一致性，Q2 与已观测 EMPTY 的冲突率；
  - 4 个世界的多样性、union recall，以及 4 个世界共同犯的错；
  - 分层：离已观测证据的远近、遮挡、窗口边界附近还是窗口内部；
  - 耗时、显存、窗口数。
- **统计**：以场景为独立单位做聚类 bootstrap。室外 Dev-5 只有 5 个独立场景。
- **复用**：如果被选中的状态正好是 G1 的 t = 0 / 20 / 50 状态，直接复用已有世界（核对哈希）；否则新生成。
- **成本粗估**：室内约 88 个状态（11 × 2 个起点 × 4 个区间），室外约 100 个（25 个起点 × 4，部分复用），合计约 50–70 GPU-h。冒烟测试后用实测值更新。
