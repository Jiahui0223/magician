## 0. 各组名称对照（图中可能出现的几种写法）

| 图里的名字 | 含义 |
|---|---|
| `ref` / Random ref. / 随机参考 | T0.3 的参考策略：在"目标位姿没去过"的合法动作里均匀随机选（都去过时在全部合法动作里选），带种子。它不是纯随机，本身就不回访 |
| `frozen` / Frozen S2S + DistP1 | 冻结的原版 Seen2Scene 世界模型 + DistP1 打分 + 贪心 |
| `C` / T1-C + DistP1 | EXP4 的 T1-C 世界模型 + DistP1 + 贪心 |
| `V2K4` / V2 K4 + Greedy | EXP5 的 V2，每个候选采样 K = 4 个未来 + DistP1 + 贪心（我们的主方法） |
| `V2K1` | 同上，K = 1 |
| `MAG-G` / MAGICIAN Greedy | 官方 MAGICIAN，只看一步（beam 1 × 1） |
| `MAG-B` / MAGICIAN Beam 10x10 | 官方 MAGICIAN，beam 搜索（宽 10、深 10） |
| `V2K4-NV` / V2 K4 + prefer-unvisited | 消融：V2K4 加上 MAGICIAN 的"只走没去过的位姿"规则，打分不变 |

**注意颜色**：
- `behaviour.png`、`paired_dots.png` 和动图用的是统一配色：V2K4 橙色，MAG-G 蓝色，MAG-B 黑色，V2K4-NV 绿色。
- `t08 / t10_curves.png` 是早期的快速作图，用的是 matplotlib 默认配色，**颜色不对应**。例如那里的 `ref` 是蓝色，看图例即可。

## 1. `figures/indoor/behaviour.png`：站点图上 8 组的行为（T0.10，22 个楼层，每层 1 条 100 步 episode）
- **怎么看**：每个子图一行一个组，条形长度是先在房屋内平均、再对 11 个房屋平均的均值，黑色误差线是房屋聚类 bootstrap 的 95% 置信区间。
- **四个子图**：

| 子图 | 含义 | 越大还是越小越好 | 数值（ref / frozen / C / V2K4 / V2K1 / MAG-G / MAG-B / V2K4-NV） |
|---|---|---|---|
| **pose revisit ratio**（位姿回访比例） | 100 步里，有多少比例的一步走到了"之前已经到过的完全相同的位姿"（同一站点、同一俯仰、同一方位）。回访时基本看不到新东西 | 越小越好 | 0.01 / **0.64** / **0.65** / 0.34 / 0.29 / 0.005 / 0.02 / 0 |
| **longest stagnation (moves)**（最长停滞） | 连续多少步覆盖率完全没有增加，取一条 episode 里最长的一段 | 越小越好 | 4.4 / 7.0 / 8.7 / 8.0 / 5.4 / 3.3 / 3.2 / **1.8** |
| **distinct stations visited**（到过的不同站点数） | 100 步里一共到过多少个不同的全景站点，表示探索的范围 | 一般越大越好 | 18.5 / 12.9 / 12.7 / 18.9 / 20.3 / 18.2 / 20.0 / **24.1** |
| **Comp@5cm after 100 moves**（完整度） | 100 步后，楼层内 GT 网格顶点中，离观测点云 5 cm 以内的比例。观测点云用每帧全部像素反投影得到 | 越大越好 | 0.49 / 0.41 / 0.40 / 0.60 / 0.61 / 0.58 / 0.61 / **0.68** |

- **这张图说明了什么**：
  1. 两个世界模型（frozen、C）约 65% 的步都在回访，到过的站点最少，Comp 最低，甚至低于随机参考。原因是它们在已经看过的空白区域里"幻想"出了增益（T0.7 的事后诊断）。
  2. V2K4 也有 34% 的回访，停滞较长。
  3. MAGICIAN 几乎不回访，因为它的规则是只走没去过的位姿。
  4. 给 V2K4 加上同样的规则（V2K4-NV）后，回访变为 0，停滞最短，站点最多，Comp 最高。所以 V2 在站点图上的主要短板是"回访"，不是预测本身。

## 2. `figures/indoor/paired_dots.png`：配对比较（T0.10，同样 22 条 episode）
- **为什么用配对**：两个方法在同一个楼层、同一个起点上各跑一次，把同一条 episode 上的结果相减，可以消除"有的楼层天生容易、有的难"的影响。
- **怎么看**：
  - 左图是 ΔAUC@100，右图是 ΔComp@5cm @100。
  - 每一行是一个比较，写作"A − B"。
  - 小圆点：每条 episode 的差值，一行 22 个点。点在 0 线右边表示这条 episode 上 A 更好。
  - 黑色菱形：房屋聚类均值。
  - 横线：95% 置信区间。**横线跨过 0 表示统计上分不出高下**；整条横线都在 0 右边，表示 A 显著更好。
  - 点的颜色只用来区分行：橙色是有 V2K4 参与的比较，绿色是 V2K4-NV 的比较，黑色是 beam 的比较。

| 行 | 比较什么 | ΔAUC@100 [95% CI]（A 更好的条数 / 22） | ΔComp@5cm | 结论 |
|---|---|---|---|---|
| ① full systems: V2K4 − MAG-B | 两个完整系统 | −0.008 [−0.064, +0.038]（15） | −0.006 [−0.082, +0.054] | 打平 |
| ② V2K4 − MAG-G | 都是贪心，但回访规则不同 | +0.012 [−0.038, +0.055]（16） | +0.018 | 打平 |
| ② same revisit rule: V2K4-NV − MAG-G | 回访规则相同，只比"预测器 + 打分" | **+0.054 [+0.025, +0.080]**（16） | **+0.098 [+0.050, +0.146]**（21） | V2 的预测器显著更好 |
| ③ beam: MAG-B − MAG-G | beam 的作用 | +0.021 [0.000, +0.043]（12） | +0.024 | 很小，CI 刚好碰到 0 |
| ablation: V2K4-NV − V2K4 | 回访规则对 V2 的作用 | **+0.042 [+0.020, +0.066]**（19） | **+0.080**（20） | 显著有帮助 |

- **标签上的小问题**：图中第 2、3 行都标了 ②。第 3 行（same revisit rule）才是 T0.11 里"比较 ②"的主比较，第 2 行是补充。图是冻结快照的一部分，这里只做说明，不改图。

## 3. `figures/t08_curves.png` 与 `figures/t10_curves.png`：平均曲线（站点图，22 条 episode，100 步）
- **两张图的关系**：两张图格式相同。t08 只有 T0.6 的 5 组（ref、frozen、C、V2K4、V2K1）；t10 再加上 T0.10 的 3 组（MAG-G、MAG-B、V2K4-NV）。
- **左图 C_obs (level scale)**：
  - 横轴：第几步（0–100）；纵轴：覆盖率 C_obs。
  - C_obs 的定义：楼层表面上 30 万个 GT 采样点中，"从某个合法站点能看到"的点算作分母，离已观测采样点 ε 以内（约 6–13 cm）的算作已覆盖。
  - 曲线下面积除以 100 就是 AUC@100，曲线越靠左上越好。
- **右图 Comp@5cm (all in-box GT vertices, full-depth cloud)**：
  - 纵轴：楼层框内全部 GT 网格顶点中，离观测点云 5 cm 以内的比例。
  - 与 C_obs 的区别：
    - 用的是网格顶点，而不是 30 万个采样点；
    - 分母是全部顶点，包括从任何站点都看不到的；
    - 观测点云用全部像素，而不是 10% 采样；
    - 阈值是固定的 5 cm。
  - 这是对齐 MAGICIAN 论文"Comp ratio"的指标。
- **怎么读**：
  - 两条世界模型曲线（frozen、C）在约 30–40 步后几乎走平：一直回访，所以停滞。
  - ref（随机参考）前期慢，但一直在涨，到 100 步超过了世界模型。
  - V2K4 / V2K1 前期上升最快。
  - t10 中 V2K4-NV（灰色）全程最高；MAG-B、MAG-G 与 V2K4 交织在一起。
- **一个细节**：这两张图的平均是 22 条 episode 直接平均，表格里是先在房屋内平均、再对房屋平均，所以终点数值与表格可能差约 0.01。要与表格完全一致的曲线，看 `figures/indoor/auc_area.png`。

## 4. `figures/t09_curves.png`：官方 MAGICIAN 发布代码在官方 MP3D 场景上的运行（T0.9）
- **内容**：MAGICIAN 发布代码自带的 5 个 MP3D 场景，每个场景跑 3 次，一共 15 条线。每种颜色是一个场景；图例只标了 rep0，同一颜色的 3 条线是同一场景的 3 次重复。
- **坐标轴**：
  - 横轴：第几个位姿（0–150）；
  - 纵轴：**MAGICIAN 发布代码自己算的覆盖率**，与我们的 C_obs 不是同一个指标，不能直接比较数值；
  - 虚线：第 100 个位姿，官方评估脚本的 AUC 只算到这里。
- **为什么曲线会下降**：发布代码的覆盖统计每个格子最多存 1,000 个点，存满后的替换会把已覆盖的点丢掉，所以曲线可能往下走。这是官方代码的性质，不是我们的问题；这也是官方脚本报告最大值的原因。
- **为什么同一场景的 3 次结果差很多**：发布代码不设随机种子。`HxpKQynjfin` 三次在 100 个位姿时分别为 0.55、0.78、0.45，其余场景差异较小（SD 约 0.01–0.03）。
- **用途**：证明官方代码在我们的环境里能按发布协议正常运行（15 / 15 次成功）。它不是与 V2 的对比。与 V2 的公平对比见 T0.10（站点图）和 T0.12（网格）。

## 5. 表格中常用指标

| 指标 | 含义 | 读法 |
|---|---|---|
| Cov@t（例如 Cov@20、Cov@100、Cov@150） | 第 t 步之后的 C_obs 覆盖率（第 t 步之后共有 t + 1 帧） | 越大越好 |
| AUC@100 / AUC@150 | 覆盖率曲线前 100 / 150 步的面积除以步数，即"平均覆盖率" | 同时反映覆盖得多和覆盖得快，越大越好 |
| Comp@5cm | 见 §3 右图 | 越大越好 |
| Comp distance（cm） | GT 顶点到观测点云的平均距离 | 越小越好；没看到的区域会把它拉得很大，所以网格实验里有几百厘米的值 |
| [a, b]（95% CI） | 以房屋为单位、有放回地重抽 10,000 次（seed 0）得到的 95% 区间 | 区间跨过 0 表示分不出高下 |
| "x/10"、"x/22" 或 n_pos | 配对差为正的 episode 条数 | 看方向是否一致；例如 4/10 表示只有 4 条是 A 更好 |
| 每步决策时间 | 规划器从收到观测到给出动作的时间。T0.10 的"独占计时"是单独测的；T0.12 的是闭环中顺带记录的，同一节点上有 4 个作业，只能作参考 | 越小越便宜 |
| 回访比例、停滞、站点数 | 见 §1 | — |
| （T0.12-C）命中真实一步最优（hit） | 打分器选出的动作，正好是用 GT 算出的真实一步增益最大的那个，这样的状态所占比例 | 越大说明一步判断越准 |
| （T0.12-C）一步遗憾（regret） | 真实最优动作的增益减去所选动作的增益，单位 ×1e−3 C_obs | 越小越好 |
| （T0.12-C）Spearman | 每个状态上，打分器给各候选的打分顺序与真实增益顺序的相关系数（−1 到 1），再取平均 | 越接近 1，排序越准 |
| （T0.12-C）剩余工作在框内的比例 | 还没覆盖、但能看到的 GT 点中，落在 V2 当前预测区域内的比例 | 越小说明 V2 能看到的价值越少 |
