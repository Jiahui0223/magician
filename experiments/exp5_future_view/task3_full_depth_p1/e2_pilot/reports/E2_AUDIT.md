## 2. 数据与标签审计
| 数组 | 是否依赖 P1 | 处理方式 |
|---|---|---|
| t\*（GT 第一交点）、候选位姿 R / T、抖动、视角编号 t / a、区域 box / dims / origin、block | 否 | 直接复用；冒烟中两组数据逐位相同 |
| 射线类别 cls、t_known / d_lo / d_hi / L_u / n_seg、粗网格 | 是 | 由 D100 P1 重算 |
| 标签类别 cat、b、y，监督掩码 lmask = UNKNOWN ∧ b ≠ 0 | 是（依赖 t_known 与未知采样） | 由冻结的 `encode_labels` 按同一规则重算 |

**冒烟（各 1 条轨迹，`e2_build check-*`）**：
| 检查 | MP3D（17DRP5sb8fy_L0 rnv_p2） | Macarons++（bannerman cg-A-0000） |
|---|---|---|
| 包装器稀疏模式 vs 冻结数据 | **78 / 78 个数组逐位相同** | **19 / 19 逐位相同** |
| D100 vs 冻结数据 | 只有 P1 相关数组不同；其余 54 个相同 | 只有 10 个 P1 相关数组不同；其余 9 个相同 |
| 构建时间 | 233 → 307 s（×1.32） | 42 → 57 s（×1.36） |

**无泄漏**：
- 构建器在状态 t 只融合记录 0..t（MP3D 按区域刷新块重放，与规划器相同）；候选相机的 t\* 只作为标签。
- D100 只是把同一批记录的全部有效像素写入 BAND。
- Macarons++ 冻结的 T-L5 重放检查（P1 必须等于存储的 L3 状态）施加在同记录的稀疏孪生上，并要求稠密地图与孪生的 EMPTY 完全相同。

**监督分布随 P1 改变**（MP3D 冒烟轨迹，1,008 个视角）。这是任务定义的直接结果，不是错误：
| 量 | D10 | D100 |
|---|---|---|
| UNKNOWN 射线比例 | 55.9% | 37.9% |
| 未知区内有命中目标（HIT，b = +1）的射线 | 2.20M | 0.84M（−62%） |
| 未知区后为已知表面（KNOWN，b = −1） | 0.76M | 1.02M |
| 不可行标签（INF_BAND 等） | 0.28M | 0.17M |

- **含义**：E2-D100 每步有效监督射线更少，而且集中在真正未观测的区域。
- **损失口径**：两组都是"每条有效射线的平均"，量级可比；但被监督的射线集合不同。
- **为什么不能统一**：若强行让两组监督同一批射线，就会与推理时的输入不一致，所以不这样做。

**同样本索引**：
- 采样器只使用 numpy RNG `[seed 0, rank]`、轨迹列表、（轨迹, t）状态和视角行，这些在两组中完全相同（上表已验证）。
- 两组都用 4 卡 DDP，按 rank 轮转分片，所以抽到的状态、视角和陈旧度序列完全相同。
- 训练前由 `e2_train.guard()` 检查 D100 数据完整（MP3D 237 条、Macarons++ 180 条），不完整则 STOP。

## 5. 开发集固定状态
- **MP3D VALSEL**：9 个楼层（6 个 val 房屋，不含 5 个评估楼层，也不含官方 test），每条轨迹 10 个状态，共 90 个。
  - oracle 由 `e2_valsel_oracle.py` 计算：用 t21_traj 的 10 万个 GT 面积采样点，eps = 0.08 k_I，候选第 t+1 帧 10% 采样。
  - 执行动作的采样与记录 t+1 逐位相同（90 / 90），否则 STOP。
- **Macarons++ Dev-3**：E1.2 的 Dev-3 状态（S_B0 + S_B2），oracle 已有。

## 6. 尚存的说明
- **Dev-3 不是盲集**：它是开发集，Task 2 的 V2 设计曾在其上调整，E1.2 也用它比较过密度。G2 的 Dev-3 结论只代表开发集。
- **VALSEL 的 oracle 与 C_obs 略有不同**：分母是全部面积采样点，而不是可见点。只影响 regret 的尺度，不影响排序比较。
