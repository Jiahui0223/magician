# Task 3 / Experiment 2 — Full-Depth Fine-Tuning Pilot 方案（草案，待批准；未启动任何训练）

## 1. 研究问题
对 D100 条件做微调，能否让 V2-Mix 更好地利用稠密几何，把 B2 的后期 Final 优势转化为更高的早期覆盖和整体 AUC？

- **密度**：D100，来自 E1.2 的推荐，标注为"冻结模型下的默认选择"。
- **评分端**：稀疏 10%，与 B2 相同。

## 2. 组别（等预算对照）
| 组 | 训练条件输入 | 初始化 | 训练 | 闭环规划器 |
|---|---|---|---|---|
| **E2-D** | D100 P1 重建的训练数据 | V2-Mix EMA@17.5k（sha256 `343f41ab…4516`） | 见 §4 | B2 方式（D100 输入 + 稀疏 DistP1） |
| **E2-S**（对照） | 现有稀疏训练数据（Task 2 原样，不重建） | 同上 | 与 E2-D 完全相同（步数、lr、种子、数据子集、采样顺序） | B0 方式 |
| 参考（不训练） | B0 = 冻结 V2-Mix + 稀疏；B2 = 冻结 V2-Mix + D100 输入 | — | — | — |

**比较方式**：
- **E2-D − E2-S**：在相同额外训练下的密度收益（主比较）；
- **E2-S − B0**：额外训练本身的收益；
- **E2-D − B2**：微调相对冻结的收益。

## 3. 数据（只用合法训练划分）
**来源与选择集**：
| 部分 | 内容 | 重建方式 |
|---|---|---|
| MP3D 训练 | 61 个官方 train 房屋的 114 个楼层，228 条 150 步轨迹（Task 2 T2.1a） | 用 `t21_build.py` 原样运行，只在进程内把 `m_p1.P1Fusion` 换成 `P1FusionFull`（与 E1.2 / B2 相同的实现） |
| MP3D 选择集 | val 中 6 个房屋的 9 个楼层（VALSEL），D100 版本 | 同上 |
| Macarons++ 训练 | Train-6 去掉 S-c（138 条轨迹，`t11_build.py`） | 同样只替换 P1 类 |
| Macarons++ 选择集 | S-c | 同上 |

- **不变的部分**：标签 t*（读取现有 tstar 文件）、候选、轨迹、抖动全部不变；**只有 P1 相关的数组变化**（粗网格、投影统计、标签类别编码）。
- **不使用**：MP3D 官方 test、评估用的 5 个 val 楼层、Test-3 / Dev-3、sofia_church。
- **Pilot 规模（建议）**：MP3D 每个楼层取 1 条轨迹（114 条，随机 / 贪心各半，按楼层交替），加全部 9 个 VALSEL 楼层；Macarons++ 取全部 138 条加 S-c。两组使用同一子集（E2-S 直接读现有稀疏数据中对应的轨迹）。
- **备选**：用全部 228 条 MP3D 轨迹，数据构建成本约翻倍。

## 4. 训练设置
沿用 `t22_train_mix.py`，只新增一个包装脚本来指定数据目录和 config，**不改冻结代码**。

| 项 | 建议值 | 理由 |
|---|---|---|
| 可训练部分 | 全部 24.8M 参数（与 Task 2 相同） | 分布变化同时出现在 3D 编码器输入（BAND 占比 ×2）和每射线通道（t_known 有效率 +20 个百分点）；只训练部分模块需要新代码路径，Pilot 不引入 |
| 步数 | 5,000（Task 2 的 1/4） | Task 2 训练损失在前 1k 步就下降约 2/3（0.42 → 0.14），5k 步足以观察适应趋势 |
| lr / 调度 | 2e−5，预热 500 步，余弦到 0 | 与 Task 2 相同，避免引入新超参数 |
| 优化器 | AdamW（β 0.9 / 0.99，wd 0.01），重新初始化 | 同 Task 2 |
| batch | 64 个视角（32 MP3D + 32 Macarons++），每 batch 8 个状态，4 卡 DDP | 同 Task 2 |
| 其他 | bf16、EMA 0.999、梯度裁剪 1.0、陈旧度增强 p = 0.5（≤ 9 步，不跨刷新）、seed 0 | 同 Task 2 |
| 评估与选择 | 每 1,250 步在本组密度的选择集上计算 ES / Brier / FM 损失；按 Task 2 规则选择（相对本组第 0 步的分数，取最小，并列取后者） | 同 Task 2 |

**冒烟（启动前）**：
1. 数据构建：用 sparse 模式重建 2 条轨迹，逐位等于现有数据（sha256），确认包装没有改变别的东西；D100 版本中 t* 等非 P1 数组相同。
2. 过拟合 200 步，损失下降。
3. 短训练 1k 步，无 NaN。

## 5. 验证方案与关口
| 关口 | 内容 | 通过条件（建议，批准后冻结） |
|---|---|---|
| G1 离线 | 训练 / 验证损失曲线，ES、Brier、FM 损失（各组自身密度的选择集）；未来深度 MAE，按已观测 / 新表面分组 | E2-D 的室内 ES 与室外 ES 都不比 E2-S 差 5% 以上；否则 STOP |
| G2 固定状态 | E1.2 的全部固定状态（MP3D 184、Macarons++ 547，稀疏评分）：Early / Middle / Late regret、Top-1、Spearman、新表面 MAE | 进闭环条件：E2-D 的 Early regret 在两个数据集都 ≤ E2-S，且整体 regret 不比 E2-S 差 5% 以上 |
| G3 闭环 | MP3D 10 条（150 步）+ Macarons++ 30 条（100 步），E2-D 与 E2-S 各跑一遍，协议与 Task 2 / Task 3 相同 | 主判定按 Task 3 协议 §4，比较 E2-D − E2-S；同时报告相对 B0、B2 的差 |

## 6. 资源估算
| 项目 | 估算 | 依据 |
|---|---|---|
| D100 数据构建 | MP3D 114 + 9 条轨迹：约 20–25 进程小时；Macarons++：约 6–8 GPU-h | Task 2 稀疏构建平均 487 s / 轨迹（共享 GPU）；E1.2 实测稠密融合 ×1.7，投影不变，估计 ×1.3–1.7 |
| 训练 | 2 组 × 约 10.5 GPU-h（4 卡约 2.6 h / 组）；8 卡可两组并行 | Task 2：20k 步约 10.5 h（4 卡） |
| G1 + G2 | 约 6 GPU-h | |
| G3 | 约 8–10 GPU-h | E2-D 需同时维护两张地图，MP3D 峰值约 19 GB，与 B2 相同 |
| **合计** | **约 60–70 GPU-h**，墙钟约 1 天 | |

**显存**：B2 方式的闭环可以把稀疏地图改为只维护 BAND 的 sum / cnt（`band_dil` 只依赖这两个数组），省去重复的 EMPTY 挖空。但收益有限（约 8%），且需要先做逐位一致性验证，Pilot 不做。

## 7. 风险
- **结果可能只说明"多训练有用"**：E2-S 对照正是为此设置。
- **5k 步可能不够**：若 G1 显示损失仍在明显下降，再申请延长。
- **D100 对微调后的模型不一定最优**：E1.2 只针对冻结模型。若 E2-D 通过 G2，可再考虑 D50 的对照。

3. G1–G3 的关口条件是否同意（批准后冻结）？
4. 是否允许使用 8 卡（两组并行）？
