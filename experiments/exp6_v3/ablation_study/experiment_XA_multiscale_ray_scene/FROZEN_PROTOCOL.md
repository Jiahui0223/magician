# Experiment XA — 冻结协议（XA-v1）

2026-11-05 冻结，早于任何 XA 训练步。依据：`experiments/exp6_v3/XA_Experiment_Protocol.md`（用户任务书）。之后的任何改动都要新建版本，并在 `logs/EVENTS.md` 写明原因；不根据结果修改。

机器可读部分：`configs/model_xa_*.json`、`configs/train_xa_*.json`、`manifests/*.json`。

## 1. 不变的部分

| 项 | 内容 |

## 2. 六个变体的定义

代码：`seen2scene/v3/xa/`。六个变体 = 场景记忆 {S, M} × Query {2D, Ray, Interval}。

### 2.1 共同结构

- **替换**：T1 在瓶颈（8 × 16）处的交叉注意力被去掉，换成一个 `XABlock`。每个 XA 模型只有这一处交叉注意力。
- **注入位置**：flow U-Net 下行路径第 2 级（16 × 32，192 通道）的第二个残差块之后。增强后的特征同时进入 skip 连接和通往瓶颈的路径。
- **锚点网格**：补齐后的 64 × 128 射线图上的 16 × 32 = 512 个单元，每个单元对应 4 × 4 条打分射线。整格都是补齐列的 48 个单元被屏蔽，所以有效 Query 最多 464 个。
- **注意力**：
  - `q = W_q·LN(h_cell + E_q(query 特征))`，`h_cell` 是 Query 所属单元的 U-Net 特征；
  - `key = W_k·LN(e)`，`value = W_v·e`，`e` 是 token 经过所属尺度的线性嵌入；
  - 4 个头，维度 192；全局 token 与该 Query 自己的局部样本拼在一起做一次带掩码的 softmax；
  - 输出 `h' = h + W_o(·)`，**`W_o` 零初始化**，所以初始网络与没有交叉注意力的 T0 逐位相同。
- **接口**：`view_cond` 返回 `(cond, mem)`，`mem = (G, Q, L)` 三个 float32 张量，首维是视角数。训练器、数据代码、损失、采样器、`V3Predictor` 都不用改。
- **信息来源**：Query 和 K/V 只用候选相机的射线、当前 P1 的投影通道、编码器输入网格和编码器特征。不用标签、GT 深度或任何收益。

### 2.2 场景记忆

| | S（单尺度） | M（多尺度） |
|---|---|---|
| 全局 token | μ @8×，每视角最多 512 个，即 T1 的场景记忆 | F16 最多 256 个 + F8（μ）最多 256 个 |
| 局部样本 | 无 | 每个 Query 沿自己的射线取 16 个点，采样 F4 和 μ |
| 每视角 token 对数 | 512 × 512 = 262,144 | 512 × (512 + 16) = 270,336 |

对照：T1 为 128 × 512 = 65,536。

- **F8**：μ（16 通道，8× 体素），受 KL 约束。token 只取有观测支持的格子（band 或 free > 0 且在域内），特征为 `[μ, band8, free8]`。
- **F16**：对 μ 做带权 2× 池化。权重是域内标记，域外子格权重为 0。另外保留 band 均值、free 均值、**有观测支持的子格比例**和域内比例四个通道，所以未观测区域不会被当成空闲空间。只有支持比例 > 0 的格子成为 token。可学习投影就是该尺度的线性嵌入。
- **F4**：编码器全分辨率特征，即 `VAEEncoder._full_res` 的输出（`r0(stem([x, valid]))`，32 通道，4× 体素）。它是中间特征，**不受 KL 约束，不是高分辨率的 μ**。只在 Query 需要的点上按需采样，不展开整个网格。
- **选择规则**（每个尺度相同，沿用 T1）：格子中心在视锥内（半角 = 对角半视场 + 10°）且距离不超过最大射线量程；超过预算时按距离排序后等步长抽取。
- **坐标**：三个尺度共用 4× 网格的模型坐标系；位置编码一律用 4× 网格范围归一化，与相机位置编码一致。室内局部 P1 和室外全局 P1 都按各自的网格范围处理，不使用米制阈值。

### 2.3 三种 Query

| | 2D | Ray | Interval |
|---|---|---|---|
| Query 数 | 每单元 1 个 | 每单元 1 条代表射线 | 代表射线上的 UNKNOWN 区间，最多 512 个 |
| 特征 | 单元平均射线方向和相机位置的 Fourier 编码（T1 的 Query 编码放到 16 × 32） | 该射线的 64 维射线编码、11 个投影通道、单元内偏移、是否有 UNKNOWN、方向 / 相机位置 / UNKNOWN 包络中点的 Fourier 编码 | Ray 的特征（中点换成区间中点）+ 区间起点、终点、长度、占该射线 UNKNOWN 总长的比例、次序 one-hot、该射线区间数、是否回退 |
| 局部采样范围（仅 M） | 单元平均射线的 [0, 量程]，均匀 | UNKNOWN 包络前后各放宽一个 4× 格；没有 UNKNOWN 时为 [0, 已知命中或量程] | 区间前后各放宽一个 4× 格 |

- **代表射线**（Ray 和 Interval 共用）：单元内 UNKNOWN 长度（`L_u`）最大的射线；并列时取离单元中心最近的位置，顺序固定。
- **UNKNOWN 区间**的来源：编码器输入的 4× 网格。
  - 一个 4× 格判为 UNKNOWN 的条件：在域内且 `1 − band − free ≥ 0.5`；
  - 沿代表射线每 2 个细体素取样，只保留 `t_known` 之前、且在当前投影通道给出的 UNKNOWN 包络内的样本；连续样本成一个区间；每条射线最多 4 个；
  - 如果投影通道显示该射线有 UNKNOWN，但 4× 网格上找不到区间（例如只有近裁剪处不足一格的小段），就把它的包络当作一个区间（“回退”）。
- **区间选择**：先放所有射线的第 1 个区间（按单元光栅顺序），再放第 2 个，依此类推，放满 512 个为止。所以每条有区间的射线至少保留第 1 个区间。
- **多区间的聚合**：同一条射线的多个区间在注意力之后取平均，写回它所在的单元。区间只作为几何条件，**不改变 First-Hit 标签和概率定义**。
- **需要报告的量**：独立射线覆盖率、区间入选比例、回退比例。

## 3. 训练与选模

- 每个变体从零训练 40,000 步，每 1,000 步保存完整可恢复状态（模型、EMA、AdamW、step），每 5,000 步保存 EMA 并在 VALSEL / S-c 固定子集上验证。
- 中断后从 `ckpt_last.pt` 恢复。训练器在恢复时按 (seed, rank, step) 重新播种，所以恢复后的样本流可复现，但与不中断的运行不同。
- **选模规则**（沿用 V3 冻结规则，只用 VALSEL 和 S-c）：`score = ES_in / ES_in(5k) + ES_out / ES_out(5k)`，在 ≥ 5k 的验证点中取最小，并列取较晚。选中的 EMA 复制为 `checkpoints/<id>/final.pt` 并记录 sha256。
- 验证指标只用于选 checkpoint，**不用于决定某个变体是否进入闭环**。

## 4. 评估

### 4.1 室外（主结果）

- All-14 × 5 个官方起点 = 70 条，每条 100 步；与 CVPR Table 1 的 V3-T1 + D1 行（`V3-D1-H3-NORISK`）同起点、同噪声键、同候选规则、同覆盖口径。
- 指标（官方覆盖，不取 cummax）：`AUC@20`、`Coverage@20`、`AUC@100`；附 `AUC@50`、`Coverage@50`、`Final = C[100]`。`AUC@k = trapz(C[0..k]) / k`。
- 汇总：场景内先平均 5 个起点，再场景等权；分 Train-6、Dev-5、Test-3、Unseen-8、All-14。Test-3 不是盲测。
- 配对差：对 V3-T1 + D1 做同起点配对，以场景为单位 bootstrap 95% CI（10,000 次，seed 0），并报告胜负场景数。
- 保留 70 条曲线、逐场景表、规划时间、失败与重试记录。

### 4.2 室内（小样本 sanity）

- 固定 6 条：`eval_indoor_v1.json` 列表中的前三个楼层，各 2 个起点，150 步。
  - Z6MFQCViBuw_L0：S6、S17
  - oLBMNvg9in8_L1：S36、S78
  - QUCTc6BB5sX_L1：S34、S135
- 指标：C_obs 的 `AUC@20`、`Coverage@20`、`AUC@100`、`Coverage@100`、`AUC@150`、`Final`。
- 对照：V3-T1 + H0 在同样 6 条上的已有结果（`work_dirs/exp6_v3/eval/closed_loop/indoor/T1`）。
- 室内数值不与室外官方覆盖混合平均；不声称室内 D1 结果。

### 4.3 参照行与回归

- 参照行直接读取 Table 1 的规范记录：V3-T1 + D1、V3-T1 + H0、MAGICIAN Beam、B0、B2。
- XA 的评估链只替换模型加载器（`scripts/planner_xa.py`），模拟器接口不变。启动前用 V3-T1 走一遍 XA 的评估链做回归：
  - 室外 barts s0 必须与 Table 1 的 V3-T1 + D1 逐位一致；
  - 室内 Z6MFQCViBuw_L0 S6 必须与已有的 T1 结果逐位一致。
  回归通过则不重跑 T1 的 70 条。

## 5. 自动执行与完成标准

- **两条链并行**（用户要求尽量用满 8 张 GPU；每个模型仍按 T1 的 4-rank 配置训练）：
  - gpu114：XA-S2D → XA-SI → XA-MR
  - gpu115：XA-SR → XA-M2D → XA-MI
- 每条链按顺序对每个变体执行：训练 → 选模 → 室外 70 条 + 室内 6 条 → 聚合 → 下一个。中间不等待人工确认。
- **没有“指标不好就取消”的逻辑。** 只有工程故障会触发重试：
  - 训练中断：从 `ckpt_last.pt` 恢复，最多 8 次；
  - CUDA OOM：连续两次后改用梯度累积 2（全局 batch 不变），并记录；
  - episode 失败：室外按模拟器的逐步检查点续跑，室内用相同种子重跑，每条最多 3 次 × 3 轮。
- **COMPLETE** 的条件（缺一不可）：训练到 40,000 步并选出 checkpoint；室外 70 / 70 条各有 101 个官方覆盖值且重放校验通过；室内 6 / 6 条各有 151 个值；规划日志里的 checkpoint sha 与选中的一致；结果、表格、图和哈希都已保存。
- 无法完成的变体记为 INCOMPLETE 并写明原因，链继续执行下一个变体；INCOMPLETE 的结果不进入最终统计，也不会被标成 COMPLETE。
- 不删除任何原始结果；失败的部分输出移到 `failed/` 保留。

## 6. 对任务书的解释与偏差

| 任务书 | 实际做法 | 原因 |
|---|---|---|
| 用持久化 `sbatch` 作业和 `afterok` 依赖 | 在现有两个 Slurm 分配（3461041 / gpu114、3465477 / gpu115）内用 `setsid nohup` 的链脚本运行，带重试 | 账户 QOS 上限是 8 张 GPU，已被这两个分配占满；它们是用户的交互会话，本会话也运行在其中，不能取消。其余 L40 节点都已被别人占用 |
| 六组逐个顺序执行 | 两条链并行，每条链内部仍按顺序 | 用户要求高效使用 8 张 GPU |
| 区间来自 P1 的 UNKNOWN 连通区间 | 从 4× 编码器输入网格读取，分辨率为 4 个细体素 | 细体素的 P1 结构在训练时不可得（训练数据只存了每条射线的统计量和 4× 缓存）；这样训练和部署用的是同一段代码、同一个输入 |
| `configs/*.yaml` | JSON | 训练器只读 JSON |
| `{spatial,ray,interval}_query.py` 三个文件 | 合并为 `queries.py` | 三者共用代表射线和局部采样代码 |

## 7. 启动前的工程检查

结果见 `results/engineering_checks.json`、`logs/EVENTS.md`。这些检查只判断能否正确运行，不用于筛选效果。

- 六个变体：公共模块初始化哈希等于 T1；初始 `cond` 和速度与 T0 逐位相同；上下文张量有限且两次调用逐位一致；扰动零初始化层后所有新参数和 VAE 编码器都有梯度；采样结果在非 UNKNOWN 射线上为 0。
- 训练器的 tiny-overfit 模式（固定 batch 200 步）：损失有限并下降。
- 4-rank 的短程 profile：每步耗时与显存。
- 冒烟 checkpoint 走通室外 D1 和室内 H0 的短流程。
- V3-T1 回归（§4.3）。
